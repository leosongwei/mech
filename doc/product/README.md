## 一句话产品

浏览器里的 16 km 见方、红蓝双方三路推塔式机甲射击游戏：玩家驾驶一台分模块
受损的机甲，双臂各挂一把真实弹道的武器，沿三条大道推进、占领城镇获得前线
出生点，最终摧毁敌方指挥部。

## 术语

| 术语 | 含义 |
| --- | --- |
| 机甲 / MECH | 玩家与部分 AI 使用的双足机器，分 CHASSIS / TORSO / L.ARM / R.ARM 四个模块 |
| 模块 | 独立血条的机体部位，手臂被打掉即失去该臂武器 |
| 路 / LANE | 三条固定大道（北、西、中），AI 与波次沿路推进 |
| 前线 | 己方在该路上最靠前的 AI 单位位置，波次空投到它身后 10 个路点 |
| 城镇 | 可占领的据点（半径 170 m），9 s 占领后成为前线出生点 |
| 波次 / WAVE | 每 22 s 一波增援，双方各三条路各一批 |
| 瞄具 / OPTICS | 1x / 4x / 10x / 20x 四档倍率，改变视场角与地形网格精度 |
| 锁定 / LOCK | 红外导弹所需的目标保持，1.1 s 完成 |

## 维护规则（对人和 agent 都适用）

1. **改任何东西之前先读 `/doc/product`**，确认改动落在既有产品规则内。
2. **任何影响玩家可见行为的改动都必须登记**，包括但不限于：新增/删除界面元素、
   文案、键位、单位或武器数值、出生点与规则时间、胜负条件、调试按钮。
3. 登记顺序：先改对应页面（`flow.md` / `screens.md` / `units.md` / `weapons.md`），
   再在 `CHANGELOG.md` 顶部加一条，格式：
   `## YYYY-MM-DD · 一句话标题` + 变更点列表 + 涉及文件。
4. 只改代码不改文档 = 未完成。数值页必须与 `defs.py` / `spawner.py` 保持一致，
   改数值时同一提交里同步本文档。
5. 纯内部重构（不改玩家可见行为）不必登记，但若顺带改了行为就按第 2 条处理。
6. 文档用中文；界面上的英文原文（如 `MECH DESTROYED`、`REARM / REPAIR`）
   保持原样，不改写成中文。
