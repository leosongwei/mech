# 攻顶导弹复锁机制（已实现）

## 需求

1. 丢失锁定，正常保持飞行高度，按目标最后位置和目标速度矢量估算目标位置，向着估算位置做纯追逐，并持续凝视估算位置
2. 如果估算位置附近（镜头视锥 3 度以内，可以取得任意可打击目标的 LOS），则锁定该目标，复锁成功！（没有顺序要求，锁中谁都行，只要不是友军，代码越简单越好）
3. 可正常进入俯冲阶段，复锁逻辑一致

本质上是把**飞行**与**锁定**解耦：制导只认一个「凝视点 + 该点速度」，锁定逻辑只负责不断
刷新/重新取得这个点。

---

## 设计

### 1. 三个组件（`components.py`）

| 组件 | 类型 | 谁拥有 | 含义 |
| --- | --- | --- | --- |
| `target` | `int32` | 已有（`UNIT_COMPS` / `PROJ_COMPS`） | 当前锁定的实体 id，`-1` = 无锁 |
| `tgt_mem` | `float32[3]` | **新**，`MISSILE_COMPS` | 凝视点：车顶（目标高度 92%），无锁时按速度继续外推 |
| `tgt_vel` | `float32[3]` | **新**，`MISSILE_COMPS` | 最后一次「看见」时目标的速度矢量，无锁时冻结不动 |

`tgt_mem` 全零 = 从来没有锁定（锁定类武器不允许在无锁时发射，所以这只在调试路径上出现，
导弹就是一块带战斗部的铁，和以前一样）。

组件集是实体的类型，所以这两个组件放在 `MISSILE_COMPS` 上——只有导弹付这份内存，
子弹一行都不多付。炮射/无制导火箭/波束制导也用同一个原型，代价是每发几十字节，
换来「一发导弹要记住它看不见的东西往哪走」这件事不需要额外的类型。

### 2. 发射时（`systems/weapons.py: fire`）

```
fire(...) → 拦截型弹药原型创建后，若 kind == 3 且 target 有效:
   tgt_mem = seeker.roof(target)      # 车顶，不是履带
   tgt_vel = vel[target]
```

发射瞬间就带上目标位置与速度矢量（需求第 0 步），所以**第一帧就脱锁**（目标在发射瞬间
被打死、刚出筒就有人拉烟）时，导弹依然有东西可凝视。

### 3. 每 tick（`seeker.py: track`，由 `systems/projectiles.py` 的 `kind == 3` 分支调用）

```
有 target 且存活且敌对:
    spot = roof(target)
    if sight.why(弹位置, spot):        # 烟幕 / 地形 / 建筑 / 树冠
        写日志 + emit("seeker")        # 只进 __game.seekerLog，HUD 不提示
        target = -1
    else:
        tgt_mem = spot; tgt_vel = vel[target]      # 刷新记忆，返回 spot
无锁:
    tgt_mem += tgt_vel * dt                        # 记忆按最后速度继续飞
    if 3° 锥内有能看见的敌车: 锁定它，刷新 tgt_mem / tgt_vel
    返回 tgt_mem（有没有复锁都返回，制导不看区别）
```

- **凝视点是「车顶」而不是车速**：`defs.AIM_ROOF = 0.78 × 车高`（机甲 5.07 m，
  压在躯干命中球内 0.38 m——92% 那版在球顶之上 0.53 m，制导零偏差也会从头顶擦过去），
  和末制导的瞄准点、
  `tools/top_attack_trace.py` 都是同一个数（`flight.py` 现在直接吃这个点，
  不再自己乘这个比例）。
- **复锁判据只有两条**：① 从**导弹自己的位置**看，目标车顶与「弹 → 凝视点」连线夹角
  ≤ **3°**（`defs.SEEKER_CONE`）；② `sight.clear`（地形/建筑/树冠/烟幕）通视。
  先按夹角由小到大排序，取第一个能看见的。不判断是不是原目标、不判断机甲还是 APC
  （候选就是 `lockable`：APC 与机甲，步兵/平民本来就不能锁），只要求敌对。
- **为什么要夹角而不是「离凝视点多近」**：导弹在几百米高空，凝视点在地面，用距离门限
  会变成一条随高度变化的宽窄不定的带子；用视线夹角就是这个导引头真实的视场。

### 4. 制导（`flight.py: step`）

签名从 `(…, tgt_pos, tgt_vel, tgt_h, …)` 改成 `(…, tgt_pos, tgt_vel, …)`：`tgt_pos`
就是凝视点，`tgt_h` 不再存在。于是**参考弧、动力爬升、滑翔、300 m 内比例导引、
俯冲角**全部原封不动——它们只吃一个点和该点的速度，而「记忆」和「真车」在这个接口上
没有区别。这就是需求 3「可正常进入俯冲阶段，复锁逻辑一致」的全部实现：没有第二个
俯冲入口，也没有「脱锁后的特殊弹道」。

`tgt_pos is None` 只在从来没有锁定过时出现（一块铁）。

### 5. 数值行为（`/tmp` 里的核对脚本，同 `tools/top_attack_trace.py` 的设置）

| 场景 | 结果 |
| --- | --- |
| 锁定一路到底，目标 12 m/s 行驶 | 命中车顶（y 9.2 m，地面 4 m） |
| 飞行中目标死亡，锥内无车 | 沿记忆继续爬升—滑翔—俯冲，落在推算位置的**地面**上（不炸在原点，也不掉在中途） |
| 目标死亡，6 s 后在推算位置 40 m 处出现一辆敌方 APC | 6.0 s 复锁 → 命中新车车顶（y 6.3 m = 地面 + 0.92×APC 高） |
| 同上，新 APC 偏离视线 300 m（≈16°） | 不锁，按记忆落点 |
| 目标 2 s 拉烟 | 3.1 s 记 `smoke on the line of sight` 断锁；烟里继续按记忆飞；7.1 s 烟散复锁同一辆车；命中 |

拦截数字没有变（`tools/intercept_check.py`：攻顶 8 发全被 30 mm 近炸拦下，和以前一致），
`tools/replay.py` 900 tick 全项零漂移。

## 不做的事

- **不加新系统**：`seeker.py` 是 `combat.py` / `ballistics.py` / `flight.py` 那样的库，
  不是 tick 里的一站——它只被 `projectiles` 的制导分支调用，和伤害一样没有自己的状态。
- **不改玩家锁定**（`systems/locking.py`）：圆圈、`lock_time`、离圈即脱锁全部不动。
  导弹在弹上自己复锁，与发射者的锁定无关（发射后不管）。
- **不在客户端加提示**：复锁只有服务器日志一行（`seeker of missile N re-locked on hull M`），
  脱锁也只写服务器日志、发一个 `seeker` 事件（记进 `__game.seekerLog`）——**HUD 上
  什么也不弹**。导引头瞎没瞎，车上本来就无从知道（瞎了的弹按同一套剖面飞），
  驾驶员能看到的只有告警圈：弹不再压向自己时 `warn` 的红指针和告警音自己停。
- **不给步兵开门**：候选集是 `lockable`（APC / 机甲）。
