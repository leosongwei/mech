# 机组告警轮盘：四张表、一次遍历、一条选择规则

日期:2026-11-25
状态:已实施（2026-11-25，1.44.0，一次落地）
范围:只动机组（`ai_crew`）的"看哪儿"这一层：`Systems/AI/Watch.cs`、`Systems/AI/Suppress.cs`，
以及 `Systems/AI/Sense.cs` 里写目击记忆的一行。玩家输入、火控定律、弹道、上线格式不变。
版本:行为对玩家可见 → **1.44.0**（第二位 +1，第三位归 0），CHANGELOG 一条。
前因:[AI_sight_issues.md](AI_sight_issues.md)（1.42.0 / 1.43.0 的缺陷调查）与
[AI_sight_plan.md](AI_sight_plan.md)（孔径的原始设计）。

一句话目标:

> 把"机组在看哪儿"从**一个方位 + 一个截止时间**换成**每 20 度一格的证据表**：弹、爆、激光、
> 目击各自向自己的方向续命，孔径取分数最高的那一格，全空时才扫视；扫视本身也改成
> "挑最久没看过的那一格"，不再按固定顺序循环。

六处与计划的偏差:

* **激光写者没有翻转成 designator × 网格盒。** 计划 §3.2 设想"每台设计ator 往自己的方位格写"，
  实现时保留 `Suppress` 现有的 crew × designator 交叉——一个 4 km 的 `Wheel` 盒覆盖上百格，
  成本远高于"每台机组对自己的 18 格算一次点积"。交替误报（P1 的激光那一半）由"每格各自的
  蓄时"解决，与遍历形状无关。
* **`eye` 的语义从"每 tick +dt"改成"上次看过的时刻"。** 计划写的是老化式累加；实现写
  `world.time`，选择时取最小。只有这一个口径能同时表达"从没看过"与"很久没看"。
* **`eye` 只写中心格，不写整个窗口。** 计划 §8.5 要求清零覆盖 `g-2..g+2`；实测这样写会让
  扫视**卡在原地**——相邻格永远刚被"看过"。改为只写中心格、选取时排除 `dist <= COVER(=2)`
  且优先靠近当前格的候选，前半球 9/9 覆盖。
* **`MIN_DWELL` 被"到位才换 + 滞回"取代。** 计划里的固定驻留时长在实现中不需要：没到位就不
  换格，到位之后 `SWITCH = 1.25` 的滞回自然给出驻留。
* **`laser-same` 场景删除。** 计划 §7 第 7 行要求"两台设计ator 交替照同一方向 → 报警"。
  两台设计ator 落在同一格是几何论证而非规则，单线持续照射（`laser` 行）已经覆盖那个语义。
  换来的是 `laser-cross`：两台各照一个方位时最好的一格读到 0.00 s，正是单槽计数器会误报的
  那件事。
* **`--check gaze` 的三处布景修正。** 摘掉 `Modes.Range.Targets.run` 与
  `Modes.Range.Interceptor.run`（靶标会把机组拖进 `TARGET`、哨位会往场景里加弹）；
  `Crew()` 不武装（否则它会打掉正后方的设计ator、光束随之中断）；`Clean` 改用 `e.query()`
  而非 `world.units()`（后者删不掉 scenery 的设计ator）。`Lay` 走 `e.row_f(...)` 而不经
  `View`——`View` 对新建的 archetype 会抛 `KeyNotFound`。

## 0. 要解决的问题

今天这一层有五个单槽字段，每个只能记住"最后一件事"：

| 字段 | 组件/stride | 记住的唯一一件事 | 丢掉的东西 |
| --- | --- | --- | --- |
| `flinch` | 2 | 有没有被打、最后一发从哪来 | 另外两个方向刚打过 |
| `paint` | 1 | 有没有激光在身上、连续多少秒 | 被照的方向；多台交替时还会误报（§1.3） |
| `gaze_cmd` | 1 | 此刻想去哪 | —— |
| `gaze_t[0]`（`hold`） | 2 | 还要在交战线待多久 | 谁让它待在交战线 |
| `gaze_t[1]`（`search_clock`） | 2 | 扫到第几段 | 被打断即归零 |

它导致三类行为（调查里编号 P1/P2 与 `paint` 的单槽）:

1. **多方向火力下只跟最后一发**。`Suppress` 每 tick 只写一个方位（最近的那一发），
   `ARC` 25° 的防抖只挡"同一串"，两挺机枪从 90° 的两个方向交叉扫射时，理论上孔径会被
   拽在中间、两端都到不了（150 °/s，90° 要 0.6 s）。
2. **被打使 `hold` 续满 8 s**，且打断时 `search_clock` 归零。结果是挨打的车组事实上不再
   扫视，而扫视恢复时从"右侧 90 度"重来。
3. **`paint` 是单槽**。两台设计ator 交替照（各 0.3 s 一断）时共享的计数器不清零，累积到
   `PAINT_ARM` 就误判为"线被压在车上"；被照的方向取的是 `beam_tgt` 的查询顺序里的第一台。

结论:缺的不是参数，而是**同一时刻只能有一个方位的状态位**。

## 1. 需要几张轮盘：四张

判据不是"有几个来源"，而是**选择语义**。综合时只有两类问题:

* **该看哪边**（正向证据）→ 三张表，各自只有一个写者、一套自己的寿命与权重；
* **哪边没看过**（负向）→ 一张表，只在正向证据全空时使用。

| 轮盘 | 句柄（建议名） | 格 × 字段 | 写者 | 寿命 | 权重(分) |
| --- | --- | --- | --- | --- | --- |
| 火力来源 | `alarm` | 18 × 2 | `Suppress` 的弹与爆 | 1.5 s | 弹 1.0 / 爆 0.5 |
| 激光告警 | `laser` | 18 × 2 | `Suppress` 的激光 | 蓄满 `PAINT_ARM` 后余温 3.0 s | 2.0 |
| 目击记忆 | `tgt` | 18 × 2 | `Sense`（每次建立信念） | 8.0 s | 0.5 × `ThreatScore` |
| 扫视新鲜度 | `eye` | 18 × 1 | `Watch`（看过的方向） | 不回零，单调增长 | —— |

**为什么火力与激光不合成一张**：写者相同，但字段语义不同——火力每格只需 [余温, 权重]，
激光需要 [蓄能, 余温]（蓄能是累计、余温是衰减，且蓄能不写就不该存在）。合成一张会让
"蓄能"这一列对火力恒为 0，遍历与测试都变复杂。

**为什么不把目击记忆并进火力表**：寿命差 5 倍（1.5 对 8 s），权重来源不同（`ThreatScore`
连续值 vs 常数），且两者对"要不要回到那个方向"的回答不同。分开后每条规则一个常数、
一条检查项。

**为什么需要 `tgt` 与 `eye` 两张而不是一张**：`tgt` 回答"那边有过敌人"，`eye` 回答
"那边最近没看过"。一张表只能回答一个：合成会把"敌人刚走开的方向"与"从未看过的方向"混成
同一个数，而它们的正确处置恰好相反（前者值得再看一眼，后者值得首次搜）。

**不做的第五张：声源轮盘。** 敌方的枪口焰、发动机声在 `Sound`/`fx` 里有距离，但把它写进
轮盘会让机组对**看不见的**火力源转头，等于给 AI 开图。机组听的只有"已经打到身边的"：
弹道 30 m、爆炸 80 m（`Suppress.WHIZ` / `HEAR`）。这条边界写进 §8。

## 2. 形状

### 2.1 组件与内存

```csharp
// 18 格 × 20 度，格 i 的中心方位 = -pi + (i + 0.5) * (2pi / 18)
ecs.register("alarm", Kind.F, 36);   // 每格 [余温 s, 权重]
ecs.register("laser", Kind.F, 36);   // 每格 [蓄能 s, 余温 s]（权重与寿命是表级常数）
ecs.register("tgt",   Kind.F, 36);   // 每格 [余温 s, 权重]
ecs.register("eye",   Kind.F, 18);   // 每格 [自上次看过起的秒数]
```

* 统一以 **格中心方位**为准：写入时 `slot = floor((wrap_pi(yaw) + pi) / STEP)`，
  读取时用格中心，不用精确来向。20° 的量化意味着"看的方向"与"来向"差最多 10°；
  孔径窗口是 ±40°（覆盖 4 格），所以量化不减少任何发现能力。
* 唯一挂在机器机组上（`person` 不挂），与今天 `paint` 的挂载点相同（`Core/World.cs:294`）。
* 每车 126 个 float ≈ 504 B；实战约 220 台机器机组 → 约 111 kB 固定占用。
  嫌大时可把 `eye` 压成 U16 tick 计数、`tgt` 权重压成 U8 量化，先不做。

### 2.2 绝对方位与"背后"

格是**世界方位**（来向天然是世界坐标）。而"正后方永不扫"是一条相对于**行驶方向**的规则，
所以只有 `eye` 在读取时换算:

```
相对方位 = wrap_pi(格中心 - heading)          // heading 见 WatchColumns.heading
只在 |相对方位| <= 90 deg 的格里挑最久没看的
```

9 格（±90° 共 180°、每格 20°；边界正好落在格心上时是 10 格，取闭区间即可）。`alarm` / `laser` / `tgt` 不受此限:
来自正后方的火力**必须**能让机组回头，这是 1.42.0 起就有的行为。

### 2.3 每 tick 一次遍历

四张表在同一个 archetype 上，一次 18 格的循环里同时完成"递减"与"计分":

```csharp
float best = 0f; int best_slot = -1;
for (int s = 0; s < 18; s++)
{
    alarm[s * 2] = MathF.Max(0f, alarm[s * 2] - dt);       // 余温
    laser[s * 2 + 1] = MathF.Max(0f, laser[s * 2 + 1] - dt);
    tgt[s * 2] = MathF.Max(0f, tgt[s * 2] - dt);
    eye[s] += dt;                                          // 单调，看过即清零

    float sc = score(s);                               // §4 的定义：三张表取最大
    if (sc > best) { best = sc; best_slot = s; }
}
```

成本：每台车每 tick 18 次遍历、约 140 次浮点运算；220 台约 3.1 万次/tick，量级与今天
`Suppress` 的一次网格查询相当（实测 `Suppress` 0.146 ms/tick）。**旧路径的每 tick 分配
全部消失**（§6）。

## 3. 四个写者

### 3.1 火力来源（`alarm`）

沿用今天的两个判定，只是写进格子而不是盖一个方位:

| 来源 | 判定 | 格 | 余温 | 权重 |
| --- | --- | --- | --- | --- |
| 弹道掠过 | 扫掠段到机体中心 ≤ 30 m（`(proj_prev, pos)`，非点采样）| 反速度方向 | 1.5 s | 1.0 |
| 爆炸 | 斜距 ≤ 80 m | 爆点方位 | 1.5 s | 0.5 |

写入规则（同一格被重复命中时）:

```
if (新权重 > 格内权重) 覆盖 [余温, 权重]
else if (新权重 == 格内权重) 余温 = max(余温, 新余温)
```

即"更值得看的来源胜；同强度只续命"。弹（1.0）不会被同格的爆（0.5）顶掉，反之会被顶掉。
`GAP` 0.5 s 与 `ARC` 25° 两道防抖**下线**：串射的每一发都写同一格，只是续命，不再需要
"同向不转向"这条规则；换格由 §4 的滞回与"到位才换"负责。

### 3.2 激光（`laser`）

两列分开，这是本设计里唯一必须分格的量:

```
蓄能: 每 tick 对所有"此刻照着我"的设计ator，在其方位格 charge += dt（上限 PAINT_ARM）
      其余格 charge = 0（不是递减——断一拍即归零，语义是"连续覆盖"）
蓄满: charge >= PAINT_ARM 的格 → 该格余温 = LIFE_LASER（3.0 s）
```

* 两台交替照**不同**格：各格都不到 0.5 s，都不报警——这正是 `PAINT_ARM` 要排除的情形，
  今天的单槽实现会误报（§0 第 3 条）。
* 两台交替照**同一**格：该格连续覆盖成立，报警。语义正确。
* 被照的方向不再取查询顺序里的第一台。

写者从"每车扫全部设计ator"翻转成"每设计ator 扫网格盒里的车":

```
foreach designator:
    盒 = grid.box(设计ator 位置, LASER_RANGE)
    for 盒内每台机器机组:
        ray_sphere 预筛（Beams.ray_sphere）→ body_hit（四通道 lit / 瞄准线）→ Sight.clear
        命中 → 该车该格 charge += dt
```

判据本身一行不改（仍用 `beam_lit` 的四通道与瞄准线两条，共用 `Beams.body_hit`），
只是**不再一命中就退出**，且循环次序从 `车 × 设计ator` 变成 `设计ator × 盒内车`。
后者在实战里更省：设计ator 是一小撮（有激光的机器），盒内车是一小撮。

### 3.3 目击记忆（`tgt`）

`Sense` 每建立一次信念（`believe()` 之后的同一行）写一格:

```
slot = 目标方位的格;  余温 = LIFE_TGT (8 s);  权重 = 0.5 * ThreatScore.of(目标型号, 距离, 自己的 sight)
```

* 它**不是**第二个目标。`ai_tgt` 仍然是唯一的目标，`tgt` 只记"哪个方向有过值得打的东西"。
  两套注意力不抢写者：`ai_tgt` 由 `Sense` 的选目标分支写，`tgt` 只由"已经看见"这一事实写。
* 只有在**没有当前目标**时它才参与选择（§4），所以交战中它不影响孔径。
* 权重乘 0.5 是为了让"8 秒前看见过一台机甲"（0.5）与"刚挨了一发"（1.0）分出先后；
  要它更强或更弱就改这一个系数。

### 3.4 扫视新鲜度（`eye`）

* 每 tick 全部格 `+= dt`，不回零。
* **孔径窗口覆盖的格清零**：`gaze` 指向格 g 时，`g-2..g+2`（±40° 覆盖 4–5 格）全部清零。
  这是"看过"的唯一写者。若只清中心格，LRU 会反复重访刚看过的相邻格。
* 读取时只考虑相对行驶方向 ±90° 的 9 格（§2.2）。
* 并列时取与当前意图（`gaze_cmd`）方位最近的一格：`eye` 全零时（出生、重置比赛后）这就是
  "当前朝向"那几格，否则一台新车会在第一个 tick 就转向方位 -170° 的 0 号格。

`Watch.PATTERN`（右 90 / 正前 / 左 90 / 正前）与 `Watch.STEP`（3 s 一段）**下线**:
LRU 自然覆盖全前半球，且在被打断后接着走，不需要把扫描进度清零。

## 4. 综合：五个互斥分支

每 tick 的输入（一次 18 格遍历里已经算出）:

| 量 | 含义 |
| --- | --- |
| `known` | 有信念（`ai_tgt`）|
| `best` / `best_slot` | 三张表里最高的分数与它的格号（含背后格）|
| `cur` | **意图**所在的格：`slot_of(gaze_cmd)`，不是眼睛此刻所在的格 |
| `cur_score` | `cur` 那一格此刻的分数 |
| `arrived` | `|wrap_pi(gaze - gaze_cmd)| < TURN_EPS`，`TURN_EPS` 0.09 rad（约 5°，一个 tick 的行程）|
| `lru` | 前半球（相对 heading ±90°）里 `eye` 最大的格 |

**五个互斥分支**，自上而下，最后一支兜底。每支写一个 `ai_gaze` 值，于是这个字节就是
"这一 tick 孔径为什么在这儿"的读数:

| # | `ai_gaze` | 条件 | 这一 tick 做什么 |
| --- | --- | --- | --- |
| 1 | `TARGET` | `known` | 每 tick 写目标方位 |
| 2 | `ALARM` | 有证据、候选格 ≠ `cur`、分数过滞回、已到位 | 写候选格心 |
| 3 | `ALARM_TURN` | 同上，但**未**到位 | 不写：上一次摆头走完再谈 |
| 4 | `ALARM_STAY` | 有证据，但候选格就是 `cur`，或分数没过滞回 | 不写 |
| 5 | `SWEEP` | `best == 0` | 需要换格且已到位则写 `lru` 格心 |

```csharp
float err = MathF.Abs(MathUtil.wrap_pi(r.gaze - r.gaze_cmd));
bool arrived = err < TURN_EPS;
int cur = slot_of(r.gaze_cmd);
float cur_score = score(cur);

if (known)                                  // 1
{
    r.gaze_cmd = MathF.Atan2(p.z - r.eye.z, p.x - r.eye.x);
    r.gaze_state = AiGaze.TARGET;
}
else if (best > 0f)                         // 2 / 3 / 4
{
    bool other = best_slot != cur;
    bool worth = best > cur_score * SWITCH; // 1.25，与 ThreatScore 同一个数
    if (!other || !worth) { r.gaze_state = AiGaze.ALARM_STAY; }
    else if (!arrived)    { r.gaze_state = AiGaze.ALARM_TURN; }
    else
    {
        r.gaze_cmd = slot_centre(best_slot);
        r.gaze_state = AiGaze.ALARM;
    }
}
else                                        // 5
{
    int want = lru_slot(c.heading(r.index, r, wheeled));
    if (want != cur && arrived) r.gaze_cmd = slot_centre(want);
    r.gaze_state = AiGaze.SWEEP;
}
```

`score(s)` 把三张表折算到同一量纲（寿命与权重见表 §1）:

```
score(s) = max( alarm.w[s] * min(1, alarm.t[s] / 1.5),     // 弹 1.0 · 爆 0.5
                2.0         * min(1, laser.t[s] / 3.0),     // 激光
                tgt.w[s]    * min(1, tgt.t[s]   / 8.0) )    // 目击 0.5 × ThreatScore
最大分: 激光 2.0 · 弹 1.0 · 目击（机甲 0.5 / 装甲车 0.25 / 火箭兵 0.13 / 步枪兵 0.05）
```

**`ai_gaze` 的五态**（`Systems/AI/Support/Tags.cs::AiGaze`，默认 0 = `SWEEP`，出生即在扫）:

| 值 | 名字 | 读法 |
| --- | --- | --- |
| 0 | `SWEEP` | 孔径由 LRU 驱动，正看着最久没看过的那一格 |
| 1 | `TARGET` | 压在信念目标上 |
| 2 | `ALARM` | 刚接受一格证据，正在转过去 |
| 3 | `ALARM_TURN` | 有更强的证据，但上一次摆头还没走完 |
| 4 | `ALARM_STAY` | 有证据，但留在当前格（已在候选格，或滞回没过）|

这是诊断字段，不上线；`--check gaze` 与战斗统计用它，`ALARM_TURN` 的占比就是"摆头被拽"
的读数（§7 检查 4）。

要点:

* **第 1 支无条件写**：信念是"打哪儿"的唯一答案，目标在动，任何"到位才换"的约束都会变成
  跟踪滞后。它也是唯一能打断轮盘与扫视的分支。
* **第 5 支同样要求到位**：从目标或证据掉到扫视时，孔径可能正朝那一格转；等它转完再改主意，
  否则会在半路反向，那正是"被拽"的最坏情形。
* **`cur_score` 按意图格算，不按眼睛此刻的格**：比较对象是"我已经决定要看的那个方向"。
* **滞回 1.25 与到位是两道独立的门**：前者防同分抖动，后者防半路改向。
* **状态值只增不改**：将来若要把"在途"与"滞回挡住"分开统计，加一个值即可（U8 字段，
  不动物理布局与上线格式）。

**于是 P1 那场争论消失了**: 有信念就盯目标（"全力接战"），没有目标就看轮盘上的证据
（"谁在打我/哪边有敌人"），两样都没有才扫。只有一条优先级序列，不存在"交战中要不要扫"
这个参数，也不需要"搜寻/交战"两态之间的切换。

## 8. 边界与陷阱

1. **轮盘只记方位证据，不记目标。** `ai_tgt` 是唯一的目标；`tgt` 表是"哪边有过敌人"。
   两者都由 `Sense` 写，但写的是两个不同的组件，不构成两个写者。
2. **不加声源轮盘。** AI 的听觉不越过 `WHIZ` / `HEAR`；否则它会对看不见的枪口转头，等于开图。
3. **不上线。** 轮盘是 `gaze` 的输入，客户端仍只读那 2 B `gaze`（`net.md` 不动）。
4. **格是绝对方位，只有 `eye` 在读取时换算相对 heading。** 车体转向后 LRU 的"前半球"随之
   移动，这是要的；而火力方向不受车体朝向影响，这也是要的。
5. **`eye` 的清零必须覆盖窗口覆盖的所有格**（`g-2..g+2`），否则 LRU 反复重访刚看过的邻居。
6. **"到位才换"与滞回是两条不同的门**，缺一条都会退化成"被火力拽着走"。
7. **`tgt` 的权重系数 0.5 是唯一的"记忆有多重要"旋钮**；把它调到 1.0 会让目击压过流弹，
   调到 0.2 会让它几乎不起作用。
8. **重置比赛**：轮盘随实体创建/销毁，`reset_match` 清场时一并消失，不需要额外清理。

## 9. 落地顺序（每一步都能单独跑 `--check gaze` / `battle`）

1. **组件 + 综合器 + `eye` + 五态。** 孔径先只由 LRU 驱动，弹/激光/目击暂时沿用今天的写者
   （把它们折算进 `alarm` / `laser`），行为上先换掉 `PATTERN`；`AiGaze` 的五个值与五个分支
   同时落下（§4），从这一天起诊断读数就有意义。验收是检查 1、2、10、11、13。
2. **写者迁移。** `Suppress` 的弹与爆改写 `alarm`；激光改成"设计ator × 盒内车"并写
   `laser` 的蓄能与余温。验收是检查 3、5、6、7。
3. **`tgt`。** `Sense` 加一行目击记忆，综合器接上。验收是检查 8、9。
4. **分配清零。** `World` 上的 scratch + `query_into`，读一次 `MECH_PERF` 战斗。验收是
   检查 12 与 `Suppress` 的逐系统读数。
5. **文档。** `docs/product/systems/ai.md` §1.3–§1.5 重写"看哪儿"这一层；
   `systems/rwr.md` §1.7 补一句"AI 侧的同一件事由轮盘分格计时"；
   `CHANGELOG.md` 顶部一条（见下）；`docs/dev/checks.md` 的 gaze 行按 §7 更新。
6. **CHANGELOG 草案**（玩家可见，≤ 8 行）:

   > **机组改用威胁轮盘：多方向火力各记各的，被打完会重新扫视（1.44.0）**

   >   的方向续命，看分数最高的那一格。两挺机枪交叉扫射时，两头都会被看过，不再只跟最近一发。
