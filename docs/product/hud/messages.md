# 消息栈、击杀行与全屏状态

> **读者**：玩家
> **一句话**：屏幕右上那一列字分别是什么、活多久；击杀行怎么读；钱在哪里冒出来；
> 挨打、阵亡和分胜负时整个屏幕是什么样。
> **数值出处**：`frontend/src/core/config.js`（`MSG_LIFE_S` / `KILL_LIFE_S` /
> `MONEY_POP_S`）、`hud/layout.js`、`hud/messages.js`、`hud/overlays.js`、
> `hud/status.js`、`app/game.js`、`fx/dispatch.js`、`app/systems/feedback.js`；
> 播报口径在 `Systems/Support/KillFeed.cs`
> **核对**：1.39.0 / 2026-11-20

## 1. 消息栈在右上角，新的一条在最上面

* 位置：告警盘那一列的左边，与来袭箭头圈左缘留 10 px；第一行距屏幕顶部 62 px，
  每行下移 17 px。
* **右对齐**：每条从同一道右边缘往左排，所以长短不一的一列仍然是一条干净的竖线。
* 同屏最多 **8 条**，列表内部最多留 40 条（旧的自然滚掉），再新的从顶部挤进来。
* 字体 12 px 等宽（`Courier New`）。普通一条是单色单行；击杀行是带底板的多段彩色行。

## 2. 每一条活多久

| 种类 | 存活 | 淡出 |
| --- | --- | --- |
| 普通提示（占领、部署、换装、拒绝、瞄准开关……） | **6 s** | 最后 1 s 线性淡到 0 |
| 击杀行 | **20 s** | 同上 |

一场仗几秒就写一条击杀，抬头看战况时往往已经过了十几秒，所以击杀行活得比提示久得多。

## 3. 普通提示的文案与颜色

| 原文 | 何时出现 | 颜色 |
| --- | --- | --- |
| `DEPLOYED AS <呼号>` | 部署成功 | 绿 `#a9f0c0` |
| `TOWN SECURED` / `TOWN LOST` | 一座城易手，按你这一方得失 | 绿 `#7ce0a0` / 红 `#ff9a9a` |
| `RE-DEPLOYED` | 重生 | 绿 `#a9f0c0` |
| `<LABEL> COMPLETE` | 整备完工（如 `REARM + REPAIR COMPLETE`） | 绿 `#a9f0c0` |
| `AIM ASSIST ON` / `AIM ASSIST OFF` | 按 `V` 或点设置里的按钮 | 绿 `#a9f0c0` |
| `NO LOCK - IR SEEKER HAS NO TARGET` | 红外导弹没锁上就扣扳机 | 红 |
| `NO LOCK - LASER HAS NO TARGET` | 激光弹没锁上就扣扳机 | 红 |
| `REARM ONLY AT BASE OR AN OWNED TOWN` | 在不能换装的地方按 `B` | 红 `#ff9a9a` |
| `ALREADY REARMING` | 有活儿在干时再按 `B` | 红 `#ff9a9a` |
| `NOTHING TO BUY` / `NOT ENOUGH MONEY` | 空草稿成交 / 余额不足 | 红 `#ff9a9a` |

服务器发来的一行提示走同一个栈、同一个 6 s，颜色是黄 `#ffe08a`：`SHOP DENIED - ...`
（`NOT ENOUGH MONEY` / `ALREADY REARMING` / `BE AT BASE / TOWN`）、
`REARM STARTED -$143 / 5.4s`、`MATCH RESTARTED`、`GOD MODE ON` / `GOD MODE OFF`、
`DEBUG SPAWN <类型>`、`DEBUG MISSILE ...`、`DEBUG TREES`。

## 4. 击杀行：三段式

```
jack killed APC with 30mm autocannon from 0.81 km away
Char Aznable[bot] killed jack with SACLOS ATGM from 2.6 km away
```

* 结构固定：`<击杀者> killed <被击杀者> with <武器> from <距离> away`。
* **配色**：击杀者与被击杀者各用**自己阵营的颜色**并加粗；` killed ` / ` with ` /
  ` from ` / ` away` 是灰 `#93a89c`；武器名与距离是浅白 `#e8f4ee` 加粗，武器名
  小写显示。
* **底板**：这一行单独画在一块半透明黑底上（`rgba(8,14,10,0.62)`，四周各留 6 px，
  高 17 px），因为 12 px 等宽字三色叠在云上读不出来。普通提示没有底板。
* **距离是那一炮打的**：从弹药出膛的位置到落点的直线距离（斜距），在出膛那一刻冻住。
  显示为千米：1 km 以内两位小数（`0.81 km`），以外一位（`2.6 km`）。没有发射点可量的
  伤害（调试旋钮直接扣血、无人引爆的爆炸）**不写这一段**，行尾停在武器名上。
* **赏金不在这行上**（见第 6 节），消息区只写字。
* 名字：玩家用大厅呼号；AI 机甲从名字池取一个驾驶员名，带 **`[bot]`** 后缀；没有名字
  的单位用类型名——`APC`、`COMMAND BASE`、`RIFLEMAN`。

## 5. 谁会被播报

一条击杀只有在**有玩家在任意一端**时才出现在屏幕上：自己的击杀、自己被击杀、别的玩家
击杀别人。两条硬规则：

* **步兵一律不播报**（步枪兵、反坦克兵、平民）——16 km 战场上他们每秒都在死，会把这一列
  刷满。他们的赏金照付，只是没有字。
* **AI 打 AI 一律不播报**——那是这场仗的大部分，与任何一位飞官无关。
* 同一阵营的误伤（自己人的爆炸、自爆）不播报——那不是任何人的击杀。
* "在击杀里"看的是**打出最后一击的那一发**：自己先打伤、最后由 AI 收掉的敌人，算那条
  AI 的击杀，因此不播报。

屏幕外的同一份数据有它自己的通道（`GET /events/kills`，SSE，给脚本与直播叠加层这类
读者）：字段、命名与口径见 [../interfaces/kills_sse.md](../interfaces/kills_sse.md)。

## 6. `+$N` 金钱弹窗

* 拿到赏金时，**在左下角资金数字的右边**紧跟着冒出 `+$200`（绿色 15 px 加粗），2.5 s
  淡出（最后 0.8 s 淡）。
* 连杀就依次往右排，最多同时 6 个，旧的在左边先淡。
* 钱长在哪个数字上就在哪个数字旁边说，所以它不是一条消息：击杀行是字，弹窗是账。
* 击杀反馈除此之外**没有任何提示音**，也不闪屏。

## 7. 受击红框与后坐

* **挨打**：屏幕四周泛起一圈红色径向渐变（中心留洞，不挡视线），强度按这一帧掉的血量
  累加、每秒衰减；**没有音效**——挨打只有这一道红闪，因为机炮连发时一声一响会把耳朵
  占满。命中、击杀、导弹被击落都不再各响一声。
* **自己开火**的后坐：火箭弹 / 激光弹 / 攻顶弹出管时一次明显的推背抖动；105 mm 单发
  是机炮的十几倍（5 s 一发，可以很大）；机炮每一发起一点轻微抖动，连发会叠成持续的
  震动。
* **附近爆炸**会抖一下，幅度随距离线性衰减到零（车毁爆炸传得比弹着远）。
* 抖动幅度按倍率缩小（20× 下几乎不可见），且衰减很快，不会积累成持续摇晃。

## 8. 死亡屏

整个屏幕覆一层暗红（`rgba(40,0,0,0.32)`），正中四行：

```
MECH DESTROYED
RE-DEPLOY IN 7.4s
RESPAWN ONE TOWN BACK FROM WHERE YOU FELL, OR AT THE BASE
LOADOUT LOST - STANDARD ARMS ON RE-DEPLOY
```

* 第一行 34 px 淡红加粗；第二行 16 px，秒数为一位小数的倒计时；第三、四行 12 px 半透明。
* 第三行是重生规则的一句话说明：靶场服务器读 `RESPAWN ON THE RANGE FIRING LINE`（那里的
  出生点固定）。倒计时本身按阵亡地点算（己方基地边最长、敌方基地边最短），规则与秒数见
  [../rules/spawn.md](../rules/spawn.md)。
* 第四行提醒**装备随车损失**：重生一律是标准机体，买过的武器要重新买。
* 相机切换为绕**阵亡地点**的缓慢环绕镜头（半径 160 m、高 90 m，俯视那一处残骸），HUD
  其余部分保留，可以继续看战况。首次部署、还没有阵亡地点时绕己方指挥部。
* 死亡屏上**没有按钮**：重生只走倒计时（调试服务器可以按 `ESC` 到齿轮里的 `RESPAWN`
  跳过，见 [panels.md](panels.md)）。

## 9. 胜负屏

* 全屏染色：胜=墨绿（`rgba(0,40,20,0.45)`）、负=暗红（`rgba(40,0,10,0.45)`）。
* 三行字整体放在屏幕**上部 30% 处**（0 / +30 / +56 px），让开正中的准星和两门炮身——
  胜负已定，倒计时里双方还要接着打一会儿。
* 第一行 `VICTORY` / `DEFEAT`（46 px）；第二行看**是谁的指挥部没了**：赢的一方读
  `ENEMY COMMAND BASE DESTROYED`，输的一方读 `OUR COMMAND BASE DESTROYED`——刚被打败
  的人不需要被告知对面基地爆了；第三行 `NEW MATCH IN 38s`（40 s 倒计时，结束后同一张
  地图重开）。

## 10. 状态与边界

* 一条提示的生命是**客户端自己的计时**，服务器不发"消息过期"，所以刷新页面这些字就没了。
* 面板打开时消息照样在写、照样在淡——面板不冻结时间；面板开着时开火与拉烟被禁，于是
  第 7 节的受击红框照常工作，而你自己扣不动扳机。
* 队伍名单、`KILLS / DEATHS / SCORE`、右下角的 `FPS / PING / TPS / LOSS` 三行读数都在
  [hud.md](hud.md)，不在本页。

## 11. 设计与取舍

* **击杀行比提示活得久**：20 s 与 6 s 的分界是读法——提示是"刚才发生了什么"，击杀行是
  "这一仗谁在杀谁"，值得回头读。
* **底板只给击杀行**：底板是给多颜色文字用的，普通提示单色单行，加底板反而把右上角
  变成一块黑板。
* **钱与字分家**：赏金贴在它改动的那个数字旁边，于是"账"可以只回答账的问题；把 `+$200`
  塞进击杀行会让一行同时回答两件事，还会在步兵击杀（无击杀行）时丢掉反馈。
* **播报口径按"玩家在一端"**：一场仗的绝大部分是 AI 之间的战斗，按距离播报会在前线把
  整列刷满，按玩家播报则保证每一条都与某个飞官有关。
* **挨打没有声音**：这是刻意的取舍——一秒钟几十发的战场上，每一发都给一声会让告警音
  （导弹、激光）听不见，而那两种声音是会救命的。
