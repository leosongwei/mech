# 换装面板、整备进度与设置菜单

> **读者**：玩家
> **一句话**：按 `B` 打开的那张采购单每一项是什么、成交后那条进度条在等什么；
> 右上角齿轮里能调什么，以及 `H` 现在还能不能调出键位表。
> **数值出处**：`frontend/src/hud/panels/{shop,settings}.js`、`hud/status.js`（整备条）、
> `app/systems/{shop,settings}.js`、`app/panels.js`、`app/hudstate.js`（220 m 换装范围）、
> `frontend/src/shop.js`（面板上的报价）。价格、工时与整备定律只住
> [../rules/economy.md](../rules/economy.md)，本页只写面板把哪些数字摆在哪里。
> **核对**：1.39.0 / 2026-11-20

## 1. 换装面板：`B`，在基地或己方城镇

* 开门条件：**己方指挥部 220 m 内**，或**己方占领的城镇 220 m 内**；靶场服务器随处可换。
  不满足时消息栈读 `REARM ONLY AT BASE OR AN OWNED TOWN`，面板不打开。
* 有活儿在干时按 `B` 被拒：消息栈读 `ALREADY REARMING`。
* 打开时**释放鼠标锁定**，面板里用光标点击；`ENTER` 成交、`ESC`（或 `B`、右上角 `X`）
  关闭。两个面板互斥：开着设置菜单按 `B`，设置先关。
* 面板铺在一块覆盖全屏的半透明遮罩上，居中一张卡片（宽 ≤980 px 或视口 90%，高 ≤700 px
  或视口 92%），字号随卡片高度缩放。
* 面板打开期间**不能开火、不能拉烟**，机甲可以继续走；被击毁时面板自动关闭。

## 2. 面板里有什么

从上到下：表头、左右两条手臂、中间一列、`CHANGES` 账单、三个按钮。

| 区块 | 显示什么 |
| --- | --- |
| 表头 | 左边 `$<当前资金>`，右边 `REARM / REPAIR`，最右 `X` |
| 手臂框 | `L-ARM` / `R-ARM` 标在框上方（青 / 橙）；框内两行：武器名、`400 RDS · HP 100%`；框内第三行 `CLICK TO PICK A WEAPON`；右下角一个 `▾` / `▴` |
| 下拉列表 | 点手臂框拉出，七项可购买武器，每项两行：`名称` / `HW $本体 + RDS $弹药 = $满装`；当前装备的那项前面有 `•`，草稿选中的高亮 |
| `REARM`（每臂一个） | 补满该臂弹匣 + 备弹，按钮上写缺几发与价钱（`18 RDS  $216`）；满弹时变灰读 `FULL`；该臂已在草稿里换了武器时失效（换装自带满弹） |
| `REARM SMOKE`（中上） | `<缺几发> × $5`，末行库存 `7/10`；满库存变灰读 `FULL` |
| `REPAIR`（中下） | 需要修多少 HP 与总价（`158 HP` / `$144`）；没损伤时变灰读 `NO DAMAGE` |
| `CHANGES` | 草稿每一笔一行，右侧一列是**这一笔要花的秒数**（`2.1s`），再右侧是金额（花出去 `- $`，退回来 `+ $`）；最多显示六行，更长的截断成 `…` |
| `TOTAL` | `TOTAL: $-1025   9.2s`；余额不足时整行变红，右侧多一个 `NOT ENOUGH MONEY` |
| 按钮 | `CONFIRM (ENTER)`、`REPAIR & REARM` + `$123 · 5.9s`、`CANCEL (ESC)` |

几个细节：

* **下拉列表是浮层**：画在面板之上、优先吃点击；点空白处收起。
* **`REPAIR & REARM` 不用在草稿里点**：直接把两只手臂的弹药补满 + 所有部位修满 + 烟幕
  补满（**不换武器**）当成一单提交；按钮上就写着这一单的预计金额与时间，钱不够时变灰。
* **`CONFIRM` 在没有改动时是灰的**（余额不足时也灰）。
* **只用鼠标选武器**：下拉列表是唯一的选法，键盘只有 `ENTER` 成交、`ESC` 取消。
* **报价是实时算的**：改草稿、掉血、别人打你，账单立刻跟着变。
* **钱在成交那一刻扣**，而不是整备完；整备期间被击毁，这一单作废、钱不退。

## 3. 成交之后发生什么

1. 客户端把整张草稿发出去。
2. 服务器**按同一套价格重算**：够了就扣钱、把活儿记在机甲身上，回一行黄字
   `REARM STARTED -$143 / 5.4s`；不够或不合规就整单拒绝，回一行 `SHOP DENIED - ...`
   （`NOT ENOUGH MONEY` / `ALREADY REARMING` / `BE AT BASE / TOWN`）。
3. 从这一刻起面板的改动不再有意义：活儿已经开工，`B` 再也打不开面板，直到倒计时走完。
4. 倒计时结束的瞬间武器 / 弹药 / 装甲才真正接上、补满，消息栈读
   `<LABEL> COMPLETE`（如 `REARM + REPAIR COMPLETE`）。

价格（单价、工时、回收比例）不出现在本页，见 [../rules/economy.md](../rules/economy.md)；
本页只负责"面板上显示什么"。

## 4. 整备进度条

一单成交后，画面**中下部**（屏幕高度 78% 处）出现一条青色进度条：

```
              REARM + REPAIR  3.9s
        ▇▇▇▇▇▇▇▇░░░░░░░░░░░░░░░░░░░░░░
              HOLD POSITION · TRIGGERS SAFE
```

* 宽最多 420 px（视口窄时取 44%）、高 10 px，按 `已过时间 / 总时间` 填充。
* 上面一行是这一单的内容与**剩余秒数**：`WEAPON CHANGE` / `REARM` / `REPAIR` / `SMOKE`
  几种合在一起用 ` + ` 连接。
* 下面一行黄字 `HOLD POSITION · TRIGGERS SAFE`：整备期间**移动与开火都被锁死**（视线
  仍然可以转），所以这一行是提醒而不是装饰。
* 进度条走完就消失，同一瞬间武器 / 弹药 / 装甲到位，然后才是那条完成消息。

## 5. 设置菜单：右上角的齿轮

* **齿轮按钮**：屏幕最右上角，32 px 见方，距右边和顶部各 8 px，图标是 Material Symbols
  的 `settings`。告警盘是圆的，屏幕角落那块方形空白正好给它，圈和按钮互不相压。
* 它是 HUD 上**唯一可点击的元素**，并且**需要先按 `ESC` 释放鼠标**才能点；悬停时按钮
  变亮。点空白处（齿轮以外）是重新锁定指针回座舱。
* 打开一张居中深色卡片（宽 ≤560 px 或视口 84%，高度随内容伸缩）。面板打开期间鼠标是
  光标、键盘除 `ESC` 外都交还面板，开火与拉烟被禁，机甲可以继续走。

面板内容自上而下：

| 区块 | 内容 |
| --- | --- |
| 标题 | 左 `SETTINGS`，右上角 `×` |
| `SOUND` | 喇叭图标 + `-` + 主音量条（`MASTER 50%`）+ `+`；下一行警告三角 + `-` + 告警器音量条（`ALARM 50%`）+ `+` |
| `AIM` | `AIM ASSIST ON` / `AIM ASSIST OFF`（一句话说明当前状态）；开着时多一行圆圈图标 + `-` + 圈宽条（`RING 4.0x`）+ `+` |
| `VIDEO` | `EFFECTS: QUALITY` / `EFFECTS: PERFORMANCE`（一句话说明当前档位） |
| `DEBUG` | 只有服务端开了 `MECH_DEBUG=1` 才出现：`RESPAWN` / `RESTART` / `GOD ON`·`GOD OFF` |
| 底部 | `CLOSE (ESC)` |

### 5.1 两个音量

* 主音量：这是一根 0–100% 的滑条，`-` / `+` 每次 5%，点条上任意位置直接跳到该值；默认
  **50%**，存在浏览器里（刷新后保持）。
* 告警器音量：橙色条，操作完全一样，**默认 50%**。它只管导弹 / 激光两种告警音（以及
  "导引头被烟幕致盲"的那声回应），枪炮、爆炸、锁定音、换装拒绝音不受它影响——把主音量
  关小、告警器留在原处是可以的，反之亦然。

### 5.2 瞄准那根开关

* `AIM ASSIST` 按钮显示当前状态，点击即切换，**默认开启**；游戏中按 **`V`** 是同一根
  开关，消息栈读 `AIM ASSIST ON` / `AIM ASSIST OFF`，两边永远同步。
* 开着时多出圈宽那一行：`-` / `+` 每次 **0.5×**，点条上任意位置直接跳到该值，范围
  **2×–8×**，默认 **4×**。圈越大越好压，越小越挑——圈与吸附的规则见 [aim.md](aim.md)。

### 5.3 效果画质

* 两档只差在**落点 / 爆炸那些粒子怎么画到屏幕上**：`QUALITY` 是 alpha 混合（火光和烟
  连成一片柔和半透明体），`PERFORMANCE` 是同一批粒子不混合、按逐像素噪点阈值整块写下去
  （疏密就是透明度，层次和亮度不变，只是一层颗粒）。
* 后者是给"一爆炸就掉帧"的机器准备的：填充率和带宽吃紧的显卡收益最大，高端卡上差别
  很小。切换立即生效，不用重开一局。
* 渲染实现见 [../../dev/client.md](../../dev/client.md)。

### 5.4 `DEBUG` 区块（只有 `MECH_DEBUG=1` 的服务器有）

| 按钮 | 行为 | 反馈 |
| --- | --- | --- |
| `RESPAWN` | 跳过死亡倒计时立刻重生 | 死亡屏消失，消息 `RE-DEPLOYED` |
| `RESTART` | 清场重开一局（保留地图） | 消息 `MATCH RESTARTED`，全场单位重建 |
| `GOD ON` / `GOD OFF` | 切换免伤 | 按钮高亮并改字，状态取自服务端 |

状态取自服务端下发（刷新页面不会与实际状态不符）。调试消息的完整清单见
[../interfaces/debug.md](../interfaces/debug.md)。

## 6. 帮助覆盖层：`H` 现在是空开关

* 键位覆盖层**不在代码里**：`H` 仍然能按，但它只把右下角那条读数的字面在
  `H - CONTROLS` 与 `H - HIDE CONTROLS` 之间来回切换，屏幕上不会有面板出现。
* 键位表本身在**启动页**（大厅），中文说明见 [../controls.md](../controls.md)。

## 7. 状态与边界

* 两个面板**互斥**，后开的先关掉前一个；面板打开时 HUD 的齿轮不画（它自己也在面板层级
  之下）。
* **面板不是暂停**：世界照常跑，别人照常打你。开着换装面板被击毁，面板自动关闭；设置
  面板不随死亡关闭。
* 成交之后到整备结束之间，机甲**不能动、不能开火**，但视线可以转——面板已经关了。
* 靶场服务器随处可换装，所以那条 `[B] REARM / REPAIR` 提示常驻。
* 面板里的图标（齿轮、喇叭、关闭叉）来自内嵌的 Material Symbols 子集字体；字体到达之前
  用同形状的几何图元兜底，所以第一帧不会缺图。

## 8. 设计与取舍

* **换装是一次采购**：草稿 → 报价 → 成交 → 工时，这条链让"换一把 105 mm"变成一个需要
  站住 6 s 的决定，而不是战斗中的一次点击。
* **面板上写的钱与服务器收的钱是同一套算术**：两边都按 `floor(v + 0.5)` 取整，所以预览
  和账单总是同一块钱；成交时服务器重算，把预览与承诺钉在同一处。
* **整备要花时间**（服务器把这一单记成工时），于是补给有了代价：这也是重生后一律
  标准机体的另一半原因——损失与采购都要真金白银和真实秒数。
* **两个音量分开**：告警音是战斗信息，枪炮是氛围，把它们绑在一根滑条上等于逼玩家在
  "听得见导弹"和"不吵"之间选。
