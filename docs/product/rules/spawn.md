# 出生与重生

> **读者**：调参 / 维护者
> **一句话**：一台机甲重新出现在哪里、为什么要等那么久，以及第一次部署和阵亡重生
> 为什么是同一条规则。
> **数值出处**：`Core/Defs.cs` 的 `RESPAWN_AT_FRONT` / `RESPAWN_AT_HOME` / `DEFAULT_LOADOUT`，
> 以及 `Modes/Battle/BattleMode.cs` 的 `mech_spawn` / `_opening_death` / `respawn_delay`、
> `Modes/Battle/Waves.cs` 的 `respawn_town` / `clear_near`、`Core/World.cs` 的
> `base_spawn` / `spawn_mech` / `_clear_spot`
> **核对**：1.39.0 / 2026-11-20

## 1. 规则

### 1.1 出生永远从"死在哪里"往回走

阵亡的一瞬间，死亡地点被记在这名玩家身上；下一条命的位置由同一个函数算出来——**三步
选城**（1.2）。没有任何一条命是随机丢在图上的。

找不到城就算不出来，那时回自己的指挥部：**基地外 70–130 m 的一圈空地**上，
朝向敌方指挥部。第一次部署没有自己的死亡地点，于是它借一个（1.3）。

### 1.2 三步选城 A → B → C

| 步 | 问什么 | 得到什么 |
| --- | --- | --- |
| **A** | 己方城镇里，离阵亡处**最近**的一座 | 只用来确定"看哪条车道"，跨不跨线都行 |
| **B** | A 那条车道上，仍然**与己方指挥部连通**、且**没有在争夺**的城镇里离阵亡处最近的一座（A 自己合格就是 A） | 战场实际的前线 |
| **C** | 从 B 沿这条车道**朝己方基地退一座** | **就是出生点** |

* 所以"死在城边"永远出生在**身后一座城**，被敌人截断的城、正在挨打的城都不会被选中。
* B 已经是这条车道上最靠基地的一座时**没有 C**，回基地那一圈。
* 出生点在城镇**中心外 40–70 m** 的环上（城镇正中的广场是空的，见 [map.md](map.md)），
  朝向敌方指挥部。

以 `红基地 – 红1 – 红2 – 红3 – 蓝(被截断) – 红4 – 红5` 为例：

| 阵亡位置 | A | B | 重生在 C |
| --- | --- | --- | --- |
| 红1 附近 | 红1 | 红1 | **红基地**（红1 是最靠基地的一座） |
| 红2 附近 | 红2 | 红2 | 红1 |
| 红3 附近 | 红3 | 红3 | 红2 |
| 红4 附近 | 红4 | 红3（红4 被蓝城截断） | 红2 |
| 红5 附近 | 红5 | 红3 | 红2 |

"连通"与"争夺"这两个词的定义见 [map.md](map.md) 与 [../modes/battle.md](../modes/battle.md)：
一座城离了基地就不再算己方的后方，一座城圈里有敌人就不再算可供后方。

### 1.3 首次部署借一个死亡地点

新开一局的第一条命走**同一套三步**，只是替它编一个死亡地点：**随机挑一条己方还占着城的
车道，把该车道上己方最靠前的那座城当作"刚死在那里"**。

于是 A→B→C 照常走完，落在那条车道**前线身后的一座城**（前线已经是这条线上最靠基地的
一座时回基地圈）。这样双方开局站在同一条规则上：**没有谁一出场就站在最前线**。

### 1.4 倒计时：离家越远等得越短

等待时间按**被击杀地点到敌方指挥部的距离**线性插值：

```
k = clamp(到敌方指挥部的距离 / 两个指挥部之间的距离, 0, 1)
等待 = 1.5 s + (20 s − 1.5 s) × k
```

在敌方基地门口阵亡等 **1.5 s**，在自家门口阵亡等 **20 s**，两个基地的中点约 **10.8 s**。
越往前打，被打掉后的空窗期越短；越是在自家门口被偷袭，惩罚越重。这条曲线属于战斗
模式（每个模式各自给一个），规则出处见 [../modes/battle.md](../modes/battle.md)。

* 倒计时在玩家没有活着的机甲时逐 tick 递减，归零就拿出来。
* **重开一局**（设置菜单里的 `RESTART`，或 `debug_restart` 消息）用的是另一个常数
  **3 s**，不是这条曲线。

### 1.5 每条命都是一台标准机

重生出来的是**标准机体**：左臂 30mm 机炮 + 右臂无制导火箭巢（`DEFAULT_LOADOUT`）。
上一台车买的东西随车一起没了——花 $800 买的 105mm 打完那一局就得回基地再买一次。

同时被重置的还有：烟幕库存补满、正在进行的整备作业取消（买的东西不会跨死亡生效）、
上一条命的死亡地点被清掉（下一条命自己算自己的）。

## 2. 数值表

| 项目 | 数值 |
| --- | --- |
| 城镇出生点 | 城镇中心外 **40–70 m** 的环上，取 16 次找一个空地 |
| 基地出生点 | 指挥部外 **70–130 m** 的环上，取 24 次；都不行就一圈圈往外走到 420 m |
| 出生朝向 | 指向敌方指挥部 |
| 空地判据 | 本格不阻挡、6 个方位各 4 m 内不阻挡、且离任一指挥部 ≥ **55 m** |
| 重生等待 | 敌方基地门口 **1.5 s** ↔ 自家基地门口 **20 s**，按距离线性插值 |
| 重开一局后的等待 | **3 s**（战斗模式） |
| 重生装备 | `DEFAULT_LOADOUT`（30mm + 无制导火箭巢），烟幕补满，整备作业取消 |

## 3. 判定与边界

* **等待期间相机绕己方指挥部转**，战场照样能看。死亡不扣钱（见 [economy.md](economy.md)），
  被动收入照常走。
* **`respawn` 调试消息**跳过倒计时：它把剩余等待压到 0.05 s，所以是"下一个 tick 就出来"，
  而不是"立刻出现在原地"。血量、装备与位置仍按正常规则走，没有第二条重生通道。
  消息表见 [../interfaces/debug.md](../interfaces/debug.md)。
* **出生点找不到空地**时不会把车放进墙里：城镇环取 16 次，基地环取 24 次，再不行就
  按 10 m 一圈、每圈 12 个方位往外找；全都失败才落在中心点上，而移动层的脱困逻辑
  （[../systems/movement.md](../systems/movement.md)）会在同一 tick 之后把它放到最近的
  空地。
* **同一个位置可以连着重生**：一队人死在同一个路口，就会一起回到同一座城镇的环上——
  环上的点是从随机方位取的，所以不会叠在一起。
* **重生不改战场状态**：城镇归属、波次计时、赏金都不因为一次重生而变化。
* 靶场的出生点与等待时间是靶场自己的规则（固定出生圈、1 s 重开），见
  [../modes/range.md](../modes/range.md)。
