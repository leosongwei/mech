# 界面说明

界面分两层：DOM（启动页/大厅）与 Canvas（HUD、设置菜单与 3D 场景）。
所有 HUD 文字为英文；本文档用中文描述，引号内保留界面原文。

## 1. 启动页 / 大厅

单页 DOM，铺满窗口。

| 区块 | 内容 |
| --- | --- |
| 标题 | `MECH`（大字、绿色发光） |
| 副标题 | `16 KM SQUARE FRONT · RED VS BLUE · THREE LANES` |
| 版本号 | 副标题下一行小字 `v<版本>`（当前 `v1.12.3`），取自 `MechServer.csproj` 的 `<Version>`，**构建时**由 `frontend/webpack.config.js` 写进页面（见 [AGENTS.md](../../AGENTS.md) 的版本约定）；靶场（`--range`）同样显示 |
| 键位表 | 两列：`W A S D` 移动、`MOUSE` 观瞄（车身/俯仰随后追上）、`WHEEL` 瞄具、`ALT + MOUSE` 自由观察、`LMB / RMB` 左右臂、`Q` 热烟幕、`B` 换装面板、`ENTER / ESC` 面板确认/取消、`ESC` 释放鼠标（释放后点右上角齿轮开设置） |
| PILOT ID | 文本框，默认 `PILOT-<pid>`，最多 16 字符，自动全选 |
| SIDE | 三个按钮 `RED` / `BLUE` / `AUTO`，选中的按钮填色（红/蓝/绿） |
| DEPLOY | 绿色主按钮；点击后进入游戏并请求指针锁定（只生效一次，`ENTER` 不会再触发部署） |
| 状态行 | 连接进度：`CONNECTING...` → `LOADING 16 KM MAP...` → `READY`；靶场服务器为 `LOADING RANGE...` |
| 错误行 | 左下角红字：启动异常（`BOOT ERROR:`）、运行时错误（`ERROR:`）、未处理拒绝（`REJECT:`） |

靶场服务器（`--range`）下副标题改为
`WEAPON RANGE · 4 KM MAP · APC TARGETS · REARM ANYWHERE`，SIDE 选择照常生效
（`AUTO` 按人数平衡，所以第二个浏览器默认落在对面——两个窗口才能互相打，也才能
看到自己的告警圈，见 [range.md](range.md) 第 5 节）。

连接失败时状态行显示 `CONNECTION FAILED - IS THE SERVER RUNNING?`，DEPLOY 无效。

## 2. 对局 HUD（Canvas 覆盖层）

坐标基于 CSS 像素，随窗口缩放。分为下列区块：

### 2.1 小地图（左上，210×210）

* 地形缩略图（草原/道路/建筑/树林/密林/岩石/基地），边框半透明绿线。
* 城镇：小方块，颜色=持有方（紫=中立），占领进度以白色圆弧表示。
* 单位：方块点，颜色=阵营；机甲点更大；指挥部为白色大方块；平民不显示。
* **小地图画全场，不受视距限制**：单位走的是服务器单独的一条"小地图通道"
  （每点 6 B：位置 + 阵营 + 类型，3.75 Hz），而 3D 战场本身只下发视距内的东西
  （见 [flow.md](flow.md) 的"视距"一节）。小地图上一次刷新的点比 1 px（76 m）还小，
  所以 3.75 Hz 看不出跳。
* 自己：绿色圆点 + 一条白色短线指向当前**车身**朝向（观瞄可以指着别处）。

### 2.2 顶部战况条（居中）

```
WAVE 12
6:34
ALLIED BASE  ▇▇▇▇▇▇▇░░
ENEMY BASE   ▇▇▇▇░░░░░░
```

* `WAVE n`：当前波次；下一行为本局时长 `m:ss`。
* 靶场模式下首行改为 `RANGE`，并在时长下方多一行 `TARGETS n`（当前存活的蓝方
  单位数，正常为 12 个 APC 靶）。
* 两条 150×5 的指挥部完整度条，按 `当前HP / 4000` 填充，颜色为阵营色，
  上方标签为本方 `ALLIED BASE` / 敌方 `ENEMY BASE`。靶场没有指挥部，两条不显示。

### 2.3 资金与战绩（左侧，小地图下方）

* `$1234`：当前资金（大字）。
* `KILLS n   DEATHS n   SCORE n`：个人战绩，SCORE 为赏金累计。
  **KILLS 只数载具**：打死步兵（步枪兵、反坦克兵、平民）照样结算赏金、照样进 SCORE，
  但**不计入 KILLS**——那个数字是拿来比车对车的。反过来，被步兵打死仍然计 DEATHS。
* 其下为所有玩家的名字与 `击杀/死亡`，按颜色区分阵营。
* 在补给范围内时追加一行黄字 `[B] REARM / REPAIR`，按 `B` 打开换装面板
  （见 2.12）。靶场模式下这行常驻（随处可换装）。

### 2.4 模块状态（左下）

最上方一条 **168×20 的速度条**：左边 `SPEED`，右边当前地面速度，如 `83 km/h`
（超过 150 km/h 时数字与进度条变青色）；底部 3 px 细条按 `速度 / 180 km/h` 填充。
速度取的是**实测位移**（快照间位置差），所以能看到 0–180 的爬升过程。

其下**三条** 168×15 的血条：`HULL`（机体池，底盘 + 躯干合并）/ `L.ARM` / `R.ARM`，
右上角显示整数血量（机体 120、手臂各 50）。颜色随比例变化：>60% 绿、>30% 黄、其余红。

### 2.5 武器面板（底部居中，左右各一块 250×56）

| 位置 | 内容 |
| --- | --- |
| 标题行 | `L-ARM 武器名` / `R-ARM 武器名`，青色 / 橙色；手臂被毁时显示 `DESTROYED` 并整体变暗 |
| 弹药行 | `弹匣 / 备弹`；无备弹武器（火箭巢、SACLOS、红外攻顶弹）只显示单一数字 |
| 状态 | 换弹中显示黄字 `RELOADING` |
| 脚注 | `x.xkm  一句话描述` |

### 2.6 瞄具指示（武器面板上方，两行）

* 上行 `OPTICS` + 四格 `1x 4x 10x 20x`，当前档位高亮（青框）。倍率切换过程中
  右侧额外显示实时倍率，如 `7.3x`。
* 下行 `ZERO km` + 八格 `0.5 1 1.5 2 2.5 3 3.5 4`（单位 km），当前调零距离高亮
  （橙框）——就是这一炮"瞄到哪儿打到哪儿"的那个距离，`CTRL`+滚轮切换
  （**500 m 一档，0.5–4 km**，默认 1 km）。

### 2.7 准星（画面中央：一个中心叉 + 双臂各一个弹着点）

* **中心叉**（正中央一个**纯白色斜叉 ×**，大小与预判圈相仿）就是**观瞄的瞄准线**
  本身——它**瞬时**跟随鼠标，而炮管要花时间追上（车身 80°/s、俯仰 50°/s）。所有
  距离读数、预瞄圈都以它为准。
  * **叉上方的数字**是瞄准线**打到的位置的距离**（视线第一个碰到的地面 / 外墙 /
    树干 / 车辆，最多 **4000 m**）；瞄准线一路飞出去什么都没碰到时显示**红色 `-`**。
* 武器按**固定距离调零**：`CTRL`+滚轮把 `ZERO` 拨到 0.5–4 km 的某一档，炮口就
  抬到"弹道正好在这一档的距离上与瞄准线相交"的角度，然后**不再随目标变化**。
  所以准星不会在山脊线附近跳来跳去——敌车压着棱线时该怎么瞄还是怎么瞄。
* 直射/火箭手臂各有一个十字括号准星（左臂青色、右臂橙色），标的是**这一炮按当前
  调零、按该臂炮管当前实际朝向**会落到的位置（不是瞄准线所在的位置）。所以它和中心
  叉是**两件事**：目标正好在调零距离上、且炮管已经追上时，它才和中心叉重合；比调零
  距离近，它落在中心叉**下方**（打近了要往上抬），远则在上方；**甩视角的时候它会
  明显滞后**（车身/俯仰还在转），转到位才并上来。炮管指向画外时（甩得太快）该臂的
  括号**不画**，而不是假装落在屏幕中央。
* 括号右侧文本：`L 842m`，距离为预测弹着点距离；射线未命中任何单位/地形时显示 `-`。
  预测弹着点会把**建筑墙面与树干**当成地面（见 `units.md` 的建筑/树木碰撞行），所以
  对着楼射击时这个距离是到**外墙**的距离，对着树是到**树干**的距离（树冠不算）。
* 命中单位时中心多一个小圆点。
* 手臂被毁的准星整体变淡（25% 不透明度）。
* **白色小十字 `+`**：只有开启**准星锁定**、并且已经吸附住某个预瞄圈时才画（见
  2.8）。中心叉是**你在看哪里**，这个小十字是**炮口实际被指到哪里**——吸附时两者
  必然分开，所以用两种形状区分（正中是 `×`，实际瞄准方向是 `+`）。**目视方向和
  相机都不会动**，动的只有瞄具本身（车身 / 俯仰随后追上来，一如既往）。

### 2.8 预瞄：目标白框与预判圈（自动，无需按键）

* 满足条件的敌方车辆（APC、机甲）会自动获得预瞄显示，条件是：**在视口内**、
  **距离 ≤ 4 km**（调零范围）、**屏幕上够大**——车体轮廓不小于**视野高度的 3%**、
  **视线通畅**（从观察点射向目标中心的射线不得先撞上建筑、山坡、**树冠**或**烟幕**）。
  同一时刻最多显示**最近的 4 个**目标，其余不画。被挡住的目标**完全没有预瞄显示**
  （不画白框也不画预判圈），和"看不见就打不着"一致。
* **判定和红外锁定是同一套**：树按**单棵树的树冠**判（阔叶树一个球、针叶树一个锥，
  冠层高度 10–18 m），烟幕按**椭球**判。所以车在林间空隙里、或躺着在树侧边，
  照样有预瞄；钻进树冠后面或者拉烟隔开就整块消失——和导引头能不能锁上是同一个答案。
* **白框**：按车体半径与高度投影出的一个白色矩形，框住目标**当前**所在位置，
  随时间跟车移动。这是"已识别"的标记。
* **预判圈**：**每只手一个圆圈**（半径 7 px，颜色仍是左青右橙），画在该臂弹丸
  **将要命中的位置**上——把**中心叉**压到圈里就能打中目标。圈里算了两件事：
  * **提前量**：目标按自己的速度和方向在弹丸飞行时间里走过去的那一段；飞行时间是
    弹丸按当前 `ZERO` 仰角飞到目标距离的**真实弹道时间**（火箭巢这种带助推的慢弹
    不是简单的"距离 ÷ 初速"）。
  * **加速/刹车/掉头**：目标的速度还在变时，圈会再往前（或往回收）一点。这一段是
    **从快照里测出来的**——客户端每收到一帧快照就把目标的实测速度与上一帧相减，
    差值除以两帧之间的 tick 数就是它的加速度（没有别的来源：服务器不发油门）。
    测出来的值按 0.25 s 的时间常数平滑，加速/刹车/转弯因此是**连续的**一条曲线，
    不是一格一格跳的数字；一副机器能拉出的上限（机甲 9.3 m/s²、APC 8 m/s²）就是
    它的量程，型号之间的差不会被估成噪声。这项只算**飞行前 1 s**（`LEAD_ACCEL_S`）：
    转弯会让加速度的方向一直转，把一秒多的飞行全按同一个加速度外推反而会画出一个
    目标根本不会走的圆弧。实测（靶场那台来回走 16 m/s 的机甲，1.4 s 外推）：
    匀速外推的平均误差 **1.35 m → 0.67 m**，它加减速/掉头的那几帧
    **6.35 m → 2.45 m**。
  * **上抬/下压**：调零只在**调零距离**上准，比它远的敌车圈会**翘到车体上方**、
    比它近的会**压到车体下方**——翘起的量就是弹道在该距离上比瞄准线高/低多少米。
    所以"中心叉压住圈"这一件事本身就要求你把炮口抬到该抬的高度。圈的仰角是**反解**
    出来的：解"视线抬到多少度，这一炮正好落在车体上"，所以中心叉压在圈心时，左右臂
    的弹着点也会跟着压在车身上。
  * **视差**：中心叉在屏幕正中，也就是**相机**的视线（车顶观瞄镜的光轴上，高度
    即机体眼点 5.05 m）。圈的仰角与中心叉的距离读数都从**同一个视点**算，否则
    1.7 km 上就会差出一米多——看起来就是"叉在圈上面一点"。
* **连线**：从白框边缘到圆圈一条同色细线，长度直观地表示提前量。
* 两只手武器不同时两个圈**分得很开**：机炮的弹丸快，火箭巢的慢得多（3.2 km 上飞行
  2.96 s 对 5.68 s，15 m/s 的目标要提前 44 m 对 85 m），所以左右手各自解算；两只手
  装同一种武器时两圈重合。
* **不画圈的情况**：该手是制导武器（SACLOS ATGM、TOP-ATTACK IR ATGM——导弹自己
  追目标，不需要提前量）、该手模块被毁、或者解算失败（仰角超出上限）。
* 移动目标的速度取**服务器快照实测的位移速度**（指令速度在机甲侧移时偏高），
  未来位置的高度取该处**地形高度**，所以上坡下坡时的框会跟着地形起伏。
* 不做遮挡检查：框可能落在被山脊、楼或树冠挡住的点上，这时真开火弹丸会打在
  近处的地形/外墙/树干上。
* **来袭导弹也用同一只白框**（没有预判圈：弹丸不用提前量，中心叉直接压上去）：
  只有告警器**已探测**、且视线通畅的那几发才画，规则见 [rwr.md](rwr.md)。

#### 准星锁定（设置里的 `AIM ASSIST`，**默认开启**）

只管**弹道武器**（12.7 mm / 30 mm / 火箭巢 / 105 mm）——制导导弹跟着瞄准线走，
不需要提前量，所以吸附对它们没有意义（瞄具只有一条，吸附时它们跟着转而已）。
开关和预瞄圈缩放都在**设置菜单**（齿轮，第 6 节），都存在 `localStorage`。

* **圈放大**：预瞄圈半径变成普通圈的 **2–8 倍**（默认 **4×** = 14 → 56 px 直径，
  滑条 `RING n.nx` 调），可吸附的范围就是这个圈本身。
* **吸附**：**中心叉落在某个圈里**时，**实际瞄准方向自动吸附到该圈的瞄准点上**
  （即 2.8 里"中心叉压住圈心"的那一点），炮口因此直接打到那个目标；玩家的**视线和
  相机一动不动**，所以能看到白色小 `+` 落在圈里而中心 `×` 还在原处。**吸附只在
  视线通畅能画出圈的目标上发生**；按住 `ALT` 自由观察、或者打开换装 / 设置面板时
  **不吸附**（那时屏幕中央的叉不是瞄具的方向）。
* **两个目标重叠**：自动选**最近的那个敌方单位**的圈（按机体距离），另一个不吸附。
* **同一目标左右手两个圈**：圈大到一个目标的两个圈必然重叠，所以两者**并列画成
  `OO`**（同一行、等大、不相交，连线照旧连到圈上）。此时两个圈**已经不在真实位置上**
  ——它们退化成**选哪只手**的按钮：叉落在左圈就吸附到左臂的提前量，落在右圈就吸附到
  右臂的（叉落在两者之间的缝里时取更近的那个）。所以白色小 `+` 通常**不在圈心**，
  而是落在两个圈之间——那里才是真正的瞄准点（同一种武器时两臂的提前量本来就重合）。
  两只手装同一种武器时这一对圈仍然分开显示，因为它们同时是两个"选择"。
* **吸附是瞄具的转向，不是瞬移**：车身 80°/s、俯仰 50°/s 追上来，两只手臂的括号
  准星照样滞后，`+` 指示的是**炮口被指到的方向**，不是炮口现在在的方向。

### 2.9 告警圈 / 告警器 RWR（屏幕右上角，半径 78 px = **固定 3 km**）

**位置**：贴屏幕右上角，圈底下是一块纯黑不透明底，红点在任何天空/地面上都读得清。
左边紧挨着**来袭方向箭头**那个同样大小的圈，再往左是消息区；齿轮按钮在屏幕最右上角
（见第 6 节）。圈的**正上方 = 车身朝向**：观瞄转过去时圈不动，只有箭头跟着相机转。

**五个记号**，一眼可分：

| 元素 | 含义 |
| --- | --- |
| 中心绿点 | 自身 |
| 红色**圆点** | **已解算位置**（`seen`）的来袭弹：真实方位 + **真实距离** |
| 红色**实线（圆心 → 圈边），5 Hz 闪** | **只有方位**（`heard`）：听得到、定不出位置 |
| 红色**三角形 + 虚线** | 敌方激光照在自己身上 |
| 圈左侧的红色 **3D 箭头** | 最近 3 发**朝自己来**的弹，指向它在**屏幕上**的方向 |

圈上方是常数刻度 `3.0 km`，下方是烟幕库存。

**刻度是常数 3 km**：它同时是快照里制导弹的网络半径，所以圈上画得出来的东西一定
是网络上真会告诉你的东西，而光点到圆心的距离就能直接读成米数。本机的发现距离不画
成圈，它体现在"这一发有没有圆点"上。

**这一节只给盘面**。四种情况（有无位置 × 判定命中 / 掠过）、五层判据（`heard` /
`steady` / `seen` / `warn` / `aim`）、两种告警音的节拍、通视、激光告警，以及全部
推导与实测记录：见 [rwr.md](rwr.md)。

### 2.10 红外导引头圆圈（装备 TOP-ATTACK IR ATGM 时）

* 该臂的准星换成一个**圆圈**：直径 = 视口宽度 5%（1600 px 宽约 80 px），
  比普通十字准星大一圈；圆圈就是导引头的锁定范围。
* **锁定距离 4 km**：超出这个距离的车扫过去不会收缩（射程 `4000 m`，与换装面板上
  写的射程一致）；圆圈本身的像素大小不受影响。
* 圆圈**始终是该臂的颜色**（左臂青、右臂橙），锁定状态靠粗细和图形区分，
  不改色：锁定时进度弧跑满一整圈、线宽加到 3.2 px，中心出现同色菱形。
* 锁定中：沿圆周按进度画一段同色弧线，右侧文本 `L 1234m` / `R 1234m`。
* **双手都装导弹**时两个圈**一样大**，各自向本手一侧错开约 40% 半径（左圈偏左、
  右圈偏右），像两个交叠的圆，颜色各自独立，一眼能看出是哪只手的导引头在跟目标。
* 被跟踪的目标本身画一个小菱形标记，颜色取正在跟踪它的那只手的颜色。
* 目标离开圆圈立即脱锁，进度清零，圆圈恢复常态。
* 被地形、建筑、树林**或烟幕**挡住的敌车**不会开始锁定**（圆圈扫过去没有任何收缩），
  已锁定的车滑到掩体后面或有人拉烟隔断视线则**立刻脱锁、进度清零**。
  树林按**单棵树的冠层**判定（阔叶球、针叶锥），所以林间空隙里看得见的车照常锁得上，
  只有真被树冠挡住时才断锁。
* 锁定过程中伴随断续提示音，完成后转为稳定音；无目标锁定失败时提示
  `NO LOCK - IR SEEKER HAS NO TARGET` / `LOCKING - HOLD SIGHTS ON TARGET`。
* 步兵与平民无法锁定（圆圈扫过也不会变成粉红）。

### 2.11 残骸

* 被击毁的步兵倒地（暗色、横躺），5 s 后消失。
* 被击毁的 APC / 机甲**先炸开一次**（直径约 30 m 的火球 + 上升的烟柱，火光约 1.5 s、
  烟柱约 5 s，屏幕明显抖动；声音是**专门的一记重爆**：先是一记低中频冲击，然后是一团
  低沉的火声、地板下的低音，最后是持续两三秒的回荡 —— 比普通命中响得多、厚得多、
  拖得长得多，并且照旧按声速延迟到达），然后变成压暗的残骸并持续冒烟，10 s 后消失。
  这团火不是装饰：见 [weapons.md](weapons.md#阵亡爆炸apc--机甲自爆)。
* 残骸不可锁定、不挡子弹、不算战斗单位。

**成交不是立刻生效，而是要花时间**（见下方「整备时间」与 2.16 进度条）。

* **武器框**：显示当前装备（或草稿里挑的那件）、总发数与该臂血量百分比。
  点一下拉出下拉列表，六项全部可购买武器，每项两行

* **`REPAIR`（中间）**：把机体池和两条手臂全修到满（共 200 HP），显示需要修多少 HP
  与总价（从零修满整机 $400，即 $2/HP）；没有损伤时变灰 `NO DAMAGE`。
* **`REARM SMOKE`（顶部）**：**每发 $10**，只补缺的那几发（缺 3 发 = $30），并清零冷却；
  按钮上写着缺几发、单价与库存（`3 × $10` / `7/10`），满库存时变灰显示 `FULL`。
* **`CHANGES`**：草稿的每一笔一行（`* 说明 ... - $金额`，回收退钱显示 `+ $`），
  每行右侧列出**这一笔要花的时间**（如 `2.1s`、`4.0s`）；最后一行
  `TOTAL: $-金额   总时间`；余额不足时 `TOTAL` 与 `NOT ENOUGH MONEY` 一起变红。
* **整备时间**（成交后才会花掉，期间机甲不能动、不能开火，见 2.16）：
  * 换掉一侧武器 **2 s**（两侧各 2 s）
  * 补满一侧弹药 **4 s**（两侧各 4 s）
  * 维修 **每 100 HP 2 s**
  * 补装烟幕 **2 s**（缺几发都是这一笔）
  * 几项可以一起下单，时间**累加**：把左臂的 30mm 机炮换成机枪 = `2 s`（装）+ `4 s`
    （装弹）= **6 s**。
* **`CONFIRM`**：把整张草稿发给服务器，服务器**再按同一套价格重算**，够了就扣钱、
  **开工**（秒数写在机甲身上，倒计时结束才把武器/弹药/装甲真正接上、补满），
  不够就整单拒绝并弹 `SHOP DENIED - ...`；已经有活儿在干时弹 `SHOP DENIED -
  ALREADY REARMING`。没有改动时 `CONFIRM` 是灰的。
* **`REPAIR & REARM`（一键）**：不用在草稿里点，直接把**两台手臂的弹药补满 +
  所有部位修满 + 烟幕补满**（不换武器）当成一单提交。按钮上直接写着这一单的
  **预计金额与时间**（如 `$143 · 5.4s`），钱不够时按钮变灰不可点。
* **键盘也能用**：面板打开时 `1`–`6` 给左臂选武器、`SHIFT`+`1`–`6` 给右臂选，
  只是把武器放进草稿；`ENTER` 确认（花钱）、`ESC` 关面板。买装备只有这一条路：
  面板关着时按数字什么也不会发生。
* 面板打开期间**不能开火、不能拉烟**，机甲可以继续走；被击毁时面板自动关闭。
  开工之后（面板已关）机甲**不能走、不能开火**，直到倒计时结束。

### 2.13 消息（右上，逐条向下）

最多同屏 8 条，每条存活 6 s 后淡出，例如：
`TOWN SECURED`（绿）/ `TOWN LOST`（红）、`RE-DEPLOYED`（绿）、
`GOD MODE ON/OFF`、`MATCH RESTARTED`、`DEPLOYED AS <名字>`、`DEBUG SPAWN <类型>`、
开工 `REARM STARTED -$143 / 5.4s`、完工 `REARM + REPAIR COMPLETE`、
拒绝 `SHOP DENIED - NOT ENOUGH MONEY` / `SHOP DENIED - ALREADY REARMING`。

**击杀消息**（kill feed）是这一列里唯一带底板的一条，一行写完一场击杀：

```
jack killed APC with 30mm autocannon +$180
Char Aznable[bot] killed jack with SACLOS ATGM
```

* 结构：`<击杀者> killed <被击杀者> with <武器>`，结尾 ` +$赏金` **只在自己击杀时**
  出现（那是自己拿到的钱，别人拿多少与自己无关）。
* 颜色：击杀者与被击杀者用**各自阵营色**（红/蓝），`killed` / `with` 灰，**武器名加粗**，
  赏金绿。整行画在一块半透明黑底板上（`rgba(8,14,10,0.62)`，四周各 6 px 留边），
  因为这一行要在天空背景上读。
* 名字：玩家用大厅呼号；AI 机甲从名字池随机取一个驾驶员名（高达系列里真正开过机甲
  作战的人，如 Amuro Ray、Char Aznable、Ramba Ral），带 **`[bot]`** 后缀；
  没有名字的单位用类型名——`APC`、`COMMAND BASE`。
* **广播口径看"有没有玩家"**：一条击杀只要有**玩家**在任意一端（自己击杀的 / 自己
  被打死的 / 别的玩家击杀了别人），就发给**所有玩家**。步兵（步枪兵 / 反坦克兵 /
  平民）的死亡一律不广播，AI 打 AI 也不广播——16 km 战场上那些每秒都在发生，会把
  这一列刷满。
* 击杀归属在**出膛那一刻**就定了：开完炮被打死、炮弹随后落地命毙，仍然算自己击毙
  （消息行与赏金照给）。
* 打掉步兵仍然正常加钱，只是没有消息行，改为一条孤零零的绿色 `+$45`。

### 2.14 右下角状态

右下角三行，从上到下：

| 行 | 内容 | 说明 |
| --- | --- | --- |
| `H - CONTROLS` / `H - HIDE CONTROLS` | 键位表开关 | 按 `H` 切换 |
| `FPS 60  DRAWS 214  INST 25256` | 渲染统计 | 帧率、绘制批次、实例数 |
| `PING  42ms  TPS 30.0  LOSS 0.00%` | 网络统计 | 见下 |

`PING` 是**往返时延**（RTT，一个来回，不除以 2；由服务器把客户端自己的 tick
编号原样回显来测，所以不需要两边时钟同步）。这一栏**固定五格宽**：三位数字（空格
补齐）+ `ms`，等宽字体下从 `0` 涨到 `999` 时后面的 `TPS`/`LOSS` 都不会左右挪；
还没有第一次回显时显示同样宽的一个 `-`。`TPS` 是服务器实测的 tick 率，正常
`30.0`；低于 30 是服务器自己扛不住，与本地网络无关。`LOSS` 是**上一秒本该发给你
却没发的快照比例**——服务器为拥塞链路跳过快照时它上升，拥塞期间读到 `100.00%`；
此时整行从灰绿变成橙色，表示"你现在看的是静止画面"。

### 2.15 受击与后坐反馈

* 受击时屏幕边缘红色径向渐变闪烁，强度随伤害衰减；**没有音效**——挨打只有这一道
  红闪（机炮连发时一声一响会把耳朵占满），命中、击杀、导弹被击落都不再各响一声。
* 击杀的反馈只有右上消息区的击杀行（`<击杀者> killed <被击杀者> with <武器> +$赏金`），
  步兵那种被抑制的行改出的孤立 `+$45` 也一样，没有提示音。
* 爆炸与开火产生屏幕轻微抖动（按倍率缩小，20x 下几乎不可见）：近处爆炸的幅度是
  原来的一半再减半（约为旧版 **1/4**）；**自己发射火箭弹 / SACLOS / 攻顶导弹**
  时有一次明显的推背抖动，**机炮每一发**带一点轻微抖动（连发会叠成持续的震动）。

## 3. 死亡界面

半透明暗红覆盖 + 居中四行：

```
MECH DESTROYED
RE-DEPLOY IN 7.4s
RESPAWN ONE TOWN BACK FROM WHERE YOU FELL, OR AT THE BASE
LOADOUT LOST - STANDARD ARMS ON RE-DEPLOY
```

第三行是重生规则的一句话说明（靶场服务器为 `RESPAWN ON THE RANGE FIRING LINE`，
那里出生点固定）。第四行提醒**装备随车损失**、重生是标准机体（见
[flow.md](flow.md#4-受伤死亡与重生)）。倒计时按**阵亡地点**算：己方指挥部边上
40 s、敌方指挥部边上 3 s，中间线性插值。

相机切换为绕己方指挥部的缓慢环绕镜头，HUD 其余部分保留（可继续观察战况）。

## 4. 胜负界面

* 全屏染色（胜=墨绿，负=暗红）+ 大字 `VICTORY` / `DEFEAT`。

  让开正中的准星和两门炮身：胜负已定，倒计时里双方还要接着打一会儿。

* 第三行 `NEW MATCH IN 38s`（40 s 倒计时，结束后同一张地图重开）。

## 6. 设置菜单（右上齿轮）

**齿轮按钮**：**屏幕最右上角**（距右边和顶部各 8 px）一个 32 px 的方形按钮，
图标为 Material Symbols 的 `settings`（齿轮）。告警圈是圆的，屏幕角落那块方形的
空白正好给它，圈和按钮互不相压；圈左侧那一列留给来袭方向箭头（见 2.9）。
它是 HUD 上唯一的可点击元素，**需要先按 `ESC` 释放鼠标**才能点；鼠标悬停时按钮
变亮。点击后弹出设置面板，面板打开期间不能开火、不能拉烟，机甲可以继续走。

面板为居中深色卡片（宽 ≤560 px，高度随内容伸缩），内容自上而下：

| 区块 | 内容 |
| --- | --- |
| 标题 | 左侧 `SETTINGS`，右上角 `×` 关闭按钮 |
| `SOUND` | 喇叭图标 + `-` + 主音量条（`MASTER n%`）+ `+`；下一行是警告三角 + `-` + 告警器音量条（`ALARM n%`）+ `+` |
| `AIM` | 一行按钮 `AIM ASSIST ON` / `AIM ASSIST OFF`；开启时下面多一行圆圈图标 + `-` + 预瞄圈缩放条（`RING n.nx`）+ `+` |
| `DEBUG` | 仅服务端 `MECH_DEBUG=1` 时出现：`RESPAWN` / `RESTART` / `GOD ON`·`GOD OFF` |
| 底部 | `CLOSE (ESC)` 按钮 |

* **主音量**：点击音量条任意位置直接跳到该值，`-` / `+` 每次 5%；范围 0–100%，
  **默认 50%**。100% 的总线增益是默认值的两倍（也就是最初混音的 6 倍），所以想更
  响就把滑块推到 50% 以上；默认 50% 正好是上一版的响度。数值存在浏览器
  `localStorage`（键 `mech.volume`），刷新后保持。
* **告警器音量（`ALARM`，橙色条）**：只管导弹 / 激光两种告警音（以及"导引头被
  烟幕致盲"的那声回应），操作方式与主音量完全一样，**默认 50%** = 上一版的响度。
  把主音量关小、告警器留在原处也可以，反之亦然。存在 `localStorage`
  （键 `mech.alarmvolume`）。主油门之外的声音（枪炮、爆炸、锁定音、换装拒绝音）不受
  它影响。
* **准星锁定（`AIM` 区块）**：按钮显示当前状态（开启时描边变黄），点击即切换，
  **默认开启**，存在 `localStorage`（键 `mech.aimassist`，`'0'` = 关）。开启时多出
  **预瞄圈缩放**那一行：`-` / `+` 每次 **0.5×**，点条上任意位置直接跳到该值，
  范围 **2×–8×**（相对普通预瞄圈半径 7 px），默认 **4×**，存在 `localStorage`
  （键 `mech.aimring`）。圈越大越好压，越小越挑。规则见 2.8 的"准星锁定"小节。
* **`DEBUG` 区块**（按下文说明，只在 `MECH_DEBUG=1` 时出现，普通服务器没有）：

| 按钮 | 行为 | 反馈 |

## 7. 声音：音速延迟与距离衰减

听到的炮声、爆炸声不再是"看见即听到"，也不是"离多远就多响"这么简单：

| 规则 | 数值 |
| --- | --- |
| 声速 | 343 m/s（20 ℃ 空气） |
| 事件保留上限 | 50 s（17 km 外车毁爆炸的波前需要这么久；还没被听到就丢弃） |
| 距离衰减 | **压缩平方反比**：25 m 以内满音量，100 m 44%、300 m 22%、1 km 11%、2 km 7.2%、8 km 3.1%（每翻倍约 −4 dB；真实的 −6 dB 在 16 km 图上是 84 dB，等于全静音） |
| 空气低通 | 距离越远高频掉得越多，两段：300 m 内基本全开（约 16 kHz），1 km 约 11.9 kHz、2 km 约 8 kHz、3 km 约 5.5 kHz，约 6.5 km 起固定 **1.4 kHz**（20 ℃ 空气吸收：125 Hz 约 0.4 dB/km，4 kHz 约 30 dB/km） |
| 低频补偿 | **不做了**：原来每个声音一条 180 Hz 低架滤波（120 m 内不补，6 km +15 dB，10 km 起封顶 +18 dB）。实测它对单独一声 5 km 外的炮声毫无作用（峰值 0.117 / 不加 0.117——那一声本来就是远场层），但一场交火里按事件累加出 +4 dB 的"低频墙"，而且它是"每个声音一个滤波器"，单独就吃掉音频 DSP 的 35%。远处的声音该有的厚度交给远场层（下面那行），补偿曲线属于一条被压缩的总线，不属于每一个事件 |
| 远场层 | 700 m 起淡入、2.6 km 全进的一层独立"闷响"，走自己的距离律 `(25/d)^0.25`（全图只掉 11 dB），**不进空气低通、也不进混响**（它本身就是山谷的回声）。**所有远场声音进一条自己的总线**（`FAR_CEIL` = −20 dBFS 的压缩器），并且**每 50 ms 最多起一个声音**：一场交火每秒几十发，逐发叠加的话这一层根本没有天花板 |
| 主链路 | 混音 → 限幅（12:1，6 dB 软拐点，2 ms 起控，触发点 **−12 dBFS**）→ 软限幅（WaveShaper，0.7 以下完全线性，往上 tanh 收到 **1.0**）→ 扬声器。浏览器在 0 dBFS 是硬削平，一声 105 mm 或 300 m 外一台车炸掉都能把波形推过 1.0，那一下的"嘶"就是破音；软限幅保证任何混音都不可能越界。触发点必须落在混音实际到不了的高度，否则软限幅就变成**常驻失真**：−8 dBFS 时单发车毁爆炸就把输出推到 0.93 峰值、**14.3% 的采样越过 0.7 拐点**，105 mm 贴脸 0.93 / 9.2%；−12 dBFS 下同样两发是 0.78 / 0.4% 和 0.86 / 0.8%，而最响的东西仍然是它们 |
| 混响 | 250 m 以内干声；越远进混响总线越多，约 2.5 km 起全湿；湿信号比直达声衰减得慢得多（远处先是回声） |
| 可听门限 | 到耳朵时低于 2% 不播放，也**不发**：机炮约 7.2 km、普通弹着 9.4 km、大爆炸 11.7 km、车毁爆炸 17 km（覆盖全图） |
| 多普勒 | 不做，音高不随相对速度变化 |

* **只看位置，不看发射时的位置**：每个声音事件记录**发射位置 + 时刻**，进入一个
  最多 50 s 的"飞行中"列表；客户端每帧用**机体当前坐标**比较声波已经走过的距离
  （343 m/s × 经过时间），波前追上机体才播放并把它踢出列表。
* **不做多普勒**：频率不变，只变响度、亮度和混响。
* **远处的声音会变闷**：真实世界里 2 km 外的炮声不是"变小"的炮声，而是**没有
  脆响的低频闷响**——空气和地面把高频吃掉了。所以距离除了压低音量还会压一条低通
  滤波器，远处只剩锤击般的中低频；同时爆炸本身按事件类型有各自的响度（弹着 <
  大爆炸 < 车毁爆炸），所以车毁的轰鸣能从全图任何位置听到，机炮声不行。
* **远处是一层单独的声音，不是近处的调小**：一层音量曲线改不了一个频谱——−30 dB
  的枪声还是枪声，只是听不见。所以 700 m 之外另起一层"闷响"（慢起音的 95→42 Hz
  正弦 + 340→120 Hz 的低通噪声边），它走自己的距离律，**全图只掉 11 dB**，绕开上面
  那条空气低通（它本身就是滤完之后的结果，再滤一遍会把它刚保住的边角又削掉）。
  权重按声源：105 mm ×1.6、30 mm ×1.0、导弹发射 ×0.4（是"咻"不是"咚"）、
  弹着 ×1.0–1.3、车毁爆炸 ×1.2 且尾巴更长。效果是 3 km 外的一声机炮到 16 km 只
  低 3.6 dB——一个山谷里的战场本来就该一直听得见，而不是过 4 km 就归于寂静。
* **远场是一层"床"，所以它是一条被压缩的总线**：一层有多少发声音都在往里灌，
  逐发叠加是没有上限的。实测一场每秒 90 个声音事件的交火，远场层直接进主混音把
  整体推高了 **8.5 dB**，音频 DSP 也从 0.96 倍实时涨到 **2.10 倍**——后者意味着
  音频线程跟不上，听到的是先一声爆音、然后整个页面没声音。所以远场声音统一进
  `far` 总线（−20 dBFS 的压缩器）并且每 50 ms 最多起一个声音：现在同样一场交火
  只比改动前高 2.5 dB（就是这一层本身），DSP 1.09 倍。
* **主链路最后一道是软限幅，不是压缩器**：压缩器有起控时间，瞬态总会漏过去一部分，
  而浏览器在 0 dBFS 是硬削平——那一下就是"破音"。所以混音最后过一级 12:1 的限幅
  （触发点 −12 dBFS），再过一条 WaveShaper（0.7 以下完全线性，往上 tanh 收到 1.0）。
  实测单发 105 mm 在座舱旁边、300 m 外一台车爆炸，两次都会把输出推到 1.07–1.12
  （被浏览器削平），现在是 0.86 和 0.78，全程没有一次越界。
* **一个声音是一条临时链，而且混音有上限**：每个 cue 临时开 6–12 个音频节点（音源、
  滤波、增益、声像、混响送出），**播完立刻拆掉自己整条链**——不拆的话它们只等垃圾
  回收，而一场交火每秒开近千个，几分钟后音频线程跟不上自己的时钟，听到的是先一声
  爆音、然后整页静音。实测（靶场、90 发/秒贴脸机炮 + 弹着，跑 4 s）：不拆时跑完
  图里还挂着 **3492 个节点**且一个也不释放，拆了之后峰值约 130、跑完回到 **1**。
  上限是同时 **48 个声音**，位置按"还要响多久"占（枪响 0.2 s、炮响 0.8 s、车毁
  4.6 s）；满了以后只有低于 −26 dB 的轻微声音被丢弃，贴脸的 105 mm 照样进。
  共用的噪声音源长 **6 s**（比场上任何声音都长，所以不会循环出"嗒"），每个包络也
  **真的落到 0**：几百个声音每秒的微小阶跃同样是一层"沙"。
* **哪些声音要发出去，由服务端按耳朵算**：每个事件按上面这条曲线算出到某位玩家
  机体位置的响度，低于 2% 就**根本不发给那位玩家**（以前是按固定距离一刀切，
  机炮和车毁同命）。地图 16 km，一场交火每秒几十发声事件，远处的绝大多数谁也
  听不见——省掉的是带宽和客户端的音频节点。机体阵亡时没有耳朵，声音事件一条都
  不发，消息类事件（击杀、占领、换装提示）照发。
* **远处的声音带混响**：所有枪炮、爆炸的声音都往一条共享的卷积混响总线
  （2.4 s 的衰减噪声尾）送一份"湿"信号，**送多少只看事件到机体的距离**——250 m
  以内是干声（贴着座舱的机炮没有回声），越远越湿，2.5 km 外为全湿。湿信号自己
  的衰减比直达声慢（8 km 处湿声比直达声高约 13 dB），所以远处的炮声是"山谷里的
  回响"，而不是"有人在隔壁打一支更轻的枪"。
* **机体自己在动**：因为每帧都用当前坐标，声音飞行期间机体移动（最高 180 km/h，
  1 km 外的一声约 3 s 内能开出去 150 m）会被自然算进去——朝声源冲过去更早听到，
  掉头跑开更晚听到，不需要假设机体停在原地。
* **即时的部分**：枪口火光、弹着特效、屏幕震动仍然立刻出现（光和冲击是瞬时的），
  只有声音迟到；电子类提示音（锁定、导弹/激光告警、换装拒绝）也照旧
  即时，它们不是空气传播的声音。
* **死亡时**：机甲不存在就没有耳朵，飞行中的事件**直接清空**——既不为一位已经不
  在的飞行员保留 50 s 的一场交火，也不播放、不报错。
