# 声音：声场、四重距离效应、总线与声部预算

> **读者**：机制维护者
> **一句话**：一声炮响怎么从世界走到耳朵里——它迟到（声场）、被距离改了四次（响度、亮度、混响、远场）、在总线里被限幅，以及一场每秒几十发的交火怎么不把音频线程拖垮。
> **数值出处**：`frontend/src/audio/levels.js`（`attenuation` / `airCutoff` / `reverberation` / `reverbLift` / `FAR_*` / `MAX_VOICES` / `CLIP_*`）、`graph.js`（总线、限幅链、远场限速）、`voices.js`（声部策略）、`field.js`（声场）、`cues.js`（每 cue 的配方与远场权重）、`synth.js`（节点链的建立与拆除）、`frontend/src/core/config.js`（`SOUND_TTL` / `EAR_NEAR`）、服务端对应物 `Core/Defs.cs` 的 `SOUND_*` 与 `Net/Netcode.cs` 的 `hearable`
> **核对**：1.39.0 / 2026-11-20

## 1. 规则

### 1.1 炮声是迟到的那种声音

一声炮响在世界里发生，在耳朵里稍后才发生。每个声学事件带着**位置、时刻与声源响度**
进入一张"在飞"的列表，客户端每帧拿声波已经走过的半径（343 m/s × 经过时间）与机甲
**此刻**的位置比较，波前追上才播放并把它从列表里踢掉。

用当前位置、而不是发射时的那一刻的位置，是这条规则的全部意义：声音飞行期间机甲还在
动（最高 180 km/h），朝声源冲过去更早听到、掉头跑开更晚听到，都不必为它做假设。

即时到达的是**不是空气传声**的那一半：枪口火光、弹着特效、屏幕震动、锁定音、两种告警
音、拒绝提示。光和电子音不迟到。

### 1.2 距离改了四次

一层音量曲线表达不了"远"，因为远处的炮声根本不是"更轻的炮声"，而是另一个声音。所以
距离分四次花掉：

| # | 效应 | 它做什么 | 它把哪一半交出去 |
| --- | --- | --- | --- |
| 1 | **衰减** `attenuation` | 压缩的平方反比：25 m 以内满音量，越远越低，全图仍有 −32 dB | 低频的厚度交给第 4 条 |
| 2 | **空气吸收** `airCutoff` | 一条低通，越远越闷：300 m 约 16 kHz、1 km 11.9 kHz、2 km 8 kHz、3 km 5.5 kHz，6.5 km 之外钉在 1.4 kHz | 响度归第 1 条，这一条只给频谱：**闷**才是耳朵读出的距离 |
| 3 | **混响比** `reverbLift` | 250 m 以内是干声，越远往共享混响送得越多（2.5 km 起全湿），湿信号自己的衰减慢于直达声 | 位置交给干声（送出在声像之前离开），房间始终是宽的 |
| 4 | **远场声部** `farBoom` | 700 m 起淡入、2.6 km 全进的一层闷响，走自己的距离律（全图只掉 11 dB） | 一切都交给它自己：它是已经滤过的回声，按 `dist` 0 播放 |

四层叠加起来，远处与近处听到的**不是同一件事**：近的是炮声，远的是山谷的回答。每种
cue 具体能到多远见 §2.5。

### 1.3 远场是一层"床"，所以它是一条被压缩的总线

远场声部不逐发混进主混音，而是全部落在 `far` 总线上，后面跟一台压缩器（`FAR_CEIL`
是这层"床"稳定下来的高度），并且**每 50 ms 最多起一个声音**（`FAR_MIN_GAP`）。理由是两个
实测：一场每秒 90 个事件的交火里，逐发叠加的远场层把整体推高了 8.5 dB，还把音频 DSP 从
0.96 倍实时顶到 2.10 倍（线程跟不上 = 先一声爆音、然后整页没声音）；接总线并限速之后
是 2.5 dB 与 1.09 倍。

权重按声源给：105 mm 1.6、30 mm 1.0、制导发射 0.4、弹着 1.0–1.3、车毁爆炸 1.2（尾巴更
长）。远场声部按 `dist` 0 播放是有意的：它已经是"穿过大气之后"的那个声音。

### 1.4 混音的最后一段：限幅再软削

```
master ─▶ limiter(12:1 / knee 6 dB / −12 dBFS / 2 ms 起控) ─▶ ×CLIP_GAIN ─▶ clip ─▶ 扬声器
```

`clip` 是一条 `WaveShaper`：0.7 以下完全线性，往上用 tanh 收到 1.0，4 倍过采样。压缩器
不是限幅器——它有起控时间，瞬态总会漏过去一点，而浏览器在 0 dBFS 是**硬削平**，那一下
的"嘶"就是破音。软削是最后一道承诺：任何混音都不可能越界。

阈值落在哪里决定软削是"接住峰值"还是"常驻失真"。−8 dBFS 时一发车毁爆炸就把输出推到
0.93 峰值、14.3 % 的采样越过 0.7 拐点，105 mm 贴脸同样 0.93 / 9.2 %——就是那层持久的
"沙沙"。−12 dBFS 下同样两发是 0.78 / 0.4 % 与 0.86 / 0.8 %，最响的东西仍然是它们。

`CLIP_GAIN` 不是口味，是测量出来的：压缩器自带 makeup，这一对设置本身就把混音抬高
1.3 dB，0.86 是把它拉回单位增益的那个数（一条恒定 cue `denied` 在目的地读 0.094，改前
改后一致）。

### 1.5 声部预算：一个声音是一条临时链

每个 cue 临时开 6–12 个节点（音源、滤波、增益、声像、混响送出），**播完在自己的
`onended` 里把整条链拆掉**。等垃圾回收等于不拆：靶场上跑 4 s 的贴脸机炮后，图里还挂着
**3492 个节点**且一个也不释放，拆了之后峰值约 130、跑完回到 1。

上限是同时 **48 个声音**（`MAX_VOICES`），位置按"还要响多久"占：几十声短促的机炮挤得
进去，十几个两秒的轰鸣挤不进去。满了以后低于 `STEAL_VOL`（−26 dB）的轻微声音被拒，贴
脸的 105 mm 照样进——拿 3 km 外的机枪换座舱旁的 105 mm 是错误的交易。

共用的噪声音源长 **6 s**（比场上任何声音都长，所以连"嗒"的接缝都不会被播放），每个包络
也**真的落到 0**：几百个声音每秒的微小阶跃同样是一层"沙"。

### 1.6 服务端先把听不见的扔掉

一个声学事件发不发，由服务端按**这位玩家的耳朵**算：`Netcode.hearable` 用同一组
`Defs.SOUND_*`（与 `levels.js` 逐行同值）算到这位机甲的响度，低于 `SOUND_FLOOR`（2 %）
就根本不发。一张 16 km 的图上每秒几十个事件，远处绝大多数谁也听不见——省掉的是带宽和
客户端的节点。机甲阵亡时没有耳朵，**声音事件一条都不发**，消息类事件（击杀、占领、换装
提示）照发。

### 1.7 方位：左/右，以及背后

事件到达时用**那一刻**的机甲位置与视角朝向定方位（所以转头改的是下一声）：

* `pan` = 方位的横向份额，−1 左 … +1 右，交给 `StereoPanner`；1 m 以内淡回正中（贴在
  座舱盖上的爆炸没有左右）；
* `behind` = 0…1 的"在背后"份额，只做成**压高音**（12 kHz → 2 kHz）：两只耳朵分不出
  前后，听感的"闷"就是全部的"背后"。

混响送出在声像之前离开总线，所以只有直达声被摆位置，房间一直是宽的。

## 3. 判定与边界

* **门限判在"到达时"**：客户端在波前到达的那一帧再判一次 `vol > SOUND_FLOOR`，所以事件
  从列表里被丢掉的两条路是一致的（服务端根本没发 / 到了发现太轻）。
* **背景标签页**：告警音自己带一个 100 ms 的时钟，不靠帧循环——`requestAnimationFrame`
  停下时两种告警音仍然按拍走，而不是冻在一个音高上。
* **音频上下文需要用户手势**：`DEPLOY` 或任意一次点击/按键之后才出声，之前是静音而不是
  报错。
* **阵亡**：在飞的列表直接清空，既不为一位已经不在了的飞行员保留 50 s 的一场交火，也不
  播放、不报错。
* **多普勒不做**：音高不随相对速度变，只变响度、亮度与混响。
* **一炮打出来的五个层次**（`HEAVY_REPORT`）是配方而不是新机制，改它不动本页任何一条律。

## 4. 设计与取舍

* **压缩的平方反比**：真实的 1/r 在 16 km 上是 84 dB 的动态范围，等于全静音。0.6 的滚降
  保住了近场的形状（100 m 的枪确实比 20 m 轻），又让 8 km 外的车体还听得见。
* **一层音量曲线改不了频谱**：−30 dB 的枪声仍然是枪声，只是听不见。所以远场另起一个声
  部，而不是把近场调小。
* **`bassLift` 已经删掉，而且是量出来的**：每个声音一条 180 Hz 低架滤波，给单独一声 5 km
  外的炮声毫无作用（峰值 0.117 / 不加 0.117——那一声本来就是远场声部），却在一场交火里按
  事件累加出 +4 dB 的"低频墙"，并单独吃掉音频 DSP 的 35 %（1.30 对 0.84 倍实时）。低频补
  偿属于一条被压缩的总线，不属于每一个事件。
* **压缩器不是限幅器**：瞬态永远漏得过去，所以最后一道是软削而不是更狠的压缩；阈值放在
  混音实际到不了的高度，否则它变成常驻失真。
* **声部预算在建立之前判**：被拒的声音一个节点都不开。决定的位置比决定本身更重要——判在
  链条建好之后，图里照样会多出十二个节点。
* **服务端过滤而不是客户端丢弃**：同样的判据放在前面，省的是带宽和节点两笔账。

## 5. 实测

读数是这些常数定稿时的记录，做法都是靶场（`./dev.sh range`）加一段脚本负载：用
`setInterval` 直接调 `g.audio.shot` / `boom` / `explosion`，或往 `g.sounds` 里推事件；
标签页在后台时用 `evaluate` 里的循环调 `g._pumpSounds()`。

| 场景 | 读数 |
| --- | --- |
| 每秒 90 个事件的交火，远场层直接进主混音 | 整体 +8.5 dB，DSP 2.10 倍实时（不稳定）|
| 同上，走 `far` 总线 + 50 ms 限速 | +2.5 dB，DSP 1.09 倍 |
| 4 s 贴脸机炮与弹着，不拆链 | 图里 3492 个节点，一个也不释放 |
| 同上，`onended` 拆链 | 峰值约 130，结束后回到 1 |
| 240 个轻微声音每秒 | 48 个槽位、约 380 个节点，负载结束回到 1 |
| 限幅阈值 −8 dBFS（一发车毁爆炸）| 0.93 峰值，14.3 % 采样过 0.7 拐点 |
| 限幅阈值 −12 dBFS（同样一发）| 0.78 峰值，0.4 % 过拐点 |
| 105 mm 贴脸，改前 / 改后 | 1.17（被浏览器硬削）/ 0.86 |
| 单声 5 km 外的炮声，有 / 无 `bassLift` | 峰值 0.117 / 0.117（它对这一声没有作用）|
| 105 mm 报告的频谱分析 | `tools/gun_report.py`（需要 `.venv` 的 numpy，只用 ffmpeg 读录音）|
