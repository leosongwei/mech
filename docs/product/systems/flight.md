# 弹的飞行：弹道、气动与两条制导律

> **读者**：机制维护者 / 调参
> **一句话**：一颗弹从出管到落地之间到底在算什么——四种 `kind` 各自的飞行定律、
> 有翼弹的空气动力、攻顶的三段制导、驾束的电机与速度表、以及它们怎么结束。
> **数值出处**：`Core/Defs.cs` 的 `WEAPONS`（`thrust` / `burn` / `ignite` / `mass` /
> `dia` / `cd0` / `k_cl` / `cl_alpha` / `cl_max` / `loft` / `apex` / `turn_r` /
> `pn_*` / `life` / `maxdist`）与 `Core/Flight.cs`、`Systems/Flights/`
> **核对**：1.46.0 / 2026-11-27

## 1. 规则

### 1.1 四种弹，两条制导律

一次扳机打出去的是一颗**真实弹丸**：它有自己的位置与速度（`pos` / `vel`）、自己的
寿命、自己的飞行状态。`kind` 决定它飞哪一条定律，也决定它在 ECS 里带哪个 tag：

| `kind` | 制导 pass | 定律 |
| --- | --- | --- |
| `bullet` | 无（`Flights.Ballistic` 自己积一步） | 只顾重力，一条抛物线 |
| `rocket` | 无（不带制导 tag） | 与有翼弹同一副气动外形，没有升力需求：推力沿速度、阻力逆速度、重力向下 |
| `saclos` | `Flights.Guidance.Saclos` | 骑激光：CLOS 制导 |
| `top` | `Flights.Guidance.Top` | 有翼滑翔 + 比例导引（PN） |
| `drone` | `Flights.Guidance.Loiter` | 保高巡航 + 盘旋搜索 + 末段比例导引 |

一 tick 的飞行块是十二个 pass，按固定次序：`Flights.Expire` 数秒 → `Flights.Arm` 写一发
新的 `first_hit_record`（并把 `proj_prev` 标成本 tick 的起点）并把本 tick 的加速度累加器
归零 → 制导（`Guidance.Top` / `Guidance.Saclos` / `Guidance.Loiter`，无制导的弹没有这一步）
→ 气动七个 stage（1.3）→ 电机（`Flights.Thrust` 是点火窗口，`Thrust.Commanded` 是常开
的调速器）→ `Flights.Integrate` 积一步并公布这一 tick 走过的腿。一整条"这颗弹是怎么结束的"
只有一条记录、一个判官，见 [../rules/damage.md](../rules/damage.md)；弹的参数表在
[../rules/weapons.md](../rules/weapons.md)。

### 1.2 子弹与无制导火箭

两者共用同一个步长：**1/30 s 半步欧拉**，与火控解算（`Ballistics.flight_at`）和
客户端的落点预测同一个式子。

* **子弹**：只扣重力。所以弹道是抛物线，仰角能闭式解出来（`solve_elevation` 的直射
  分支）。
* **无制导火箭**：弹先以 55 m/s 被发射药丢出，主发动机随后以 560 m/s² **沿它已有的
  速度方向**推到 610 m/s（约 1.05 s、约 360 m），之后无动力。它从不转鼻，也就没有第二个
  方向可去。**它和两种导弹是同一副气动外形**（`Flight.slide`，见 1.3）：80 mm、11.3 kg，
  `cd0` 0.3 加上跨音速上升项，610 m/s 时阻力就有 70 m/s²——所以熄火是速度顶点的
  那一刻，之后一路衰减：1 km 处约 546 m/s、2 km 处约 478 m/s。
* **阻力让它落得更低**：与没有阻力的同一发弹相比，火箭在 1 km 低 6.6 m、2 km 低 20 m、
  3.2 km 低 60 m。加上推力段，"仰角—落点"是一个陡函数，闭式解不存在，火控用割线法走
  六步，每一步都飞同一副外形。
* **落点的散布是巢自己的**：火箭巢 0.003 rad 的散布在 1 km 上是 3 m 的高低，而弹到那里
  时速度线几乎贴着地面（`dy/dx` 约 0.015），所以 3 m 的高低读成**一两百米的远近**——
  靶场上连打六发读到 756-997 m，准星上的标记点仍是 1006 m（它画的是一发无散布的弹）。
* **机械偏置 `bias`**：火箭巢自己上仰 0.0493 rad（≈2.83°），是这个巢的机械归零——让
  衰减后的弹在 1 km 上正好穿过瞄准线（机炮在那里几乎打平）。开火时这一项被调零解算
  吸收，只有退回原始瞄准（射线出图、超出 4 km）时才按 2.83° 直接打出去。

同一个积分器给出的飞行时间：1 km 约 2.2 s、2 km 约 4.2 s、3.2 km 约 6.9 s——所以
火箭巢读起来是"先慢后快"，而弹本身是越飞越慢的。RPG（85 mm、2.25 kg、300 m/s 上限）
是同一副外形的小一号：0.8 s 助推，800 m 处掉到 224 m/s、比无阻力的弹低 10 m。

### 1.3 有翼弹是一副气动外形，不是一条画好的曲线

攻顶弹与驾束弹是**同一种飞行体**，逐 tick 积分：点质量 + 攻角。无制导火箭是这副形体的
第三种用法：同一套积分、同一条阻力极曲线，只是升力需求恒为零（`Flight.slide`）——所以
它的机头永远压在速度线上，付的是剖面阻力与跨音速上升项。

* 制导每一步只要一个**加速度需求**（方向 + 大小）；
* 需求换成升力系数 `CL = m · a / (qS)`，钳在 `cl_max`；
* `CL` 换成攻角 `α = CL / cl_alpha`，**机头领先速度线 α**；
* 推力沿**机头**，升力**垂直速度**，阻力**逆速度**，重力永远竖直向下；
* 阻力极曲线 `CD = cd0 + k_cl · CL² + 0.4·(M − 0.8)²`：诱导阻力是**平方且不带符号**的，
  所以一次推杆和一次拉杆一样贵；跨音速那一段另加一条上升项；
* 速度上限 `maxvel` 由结构/发动机给出，与空气动力无关。

于是"急拉一次要付速度"是真的：能拉出的过载是 `q·S·cl_max / m`，而 `q` 与速度平方成正比
——**慢下来的弹不再答话**。这条公式一行三用：制导需求的上限、攻顶末段的门、驾束远距离
的射程边界。

这条链条在 ECS 里是七个 stage，每个 stage 是一个组件查询：**"哪些力作用在这颗弹上"就是
它的组件集合**。中间量因此落在组件里，一个同时拥有 `acc`、`a_dir`、`cl` 的实体就是"一副
会算气动的飞行体"。

| # | stage | 读 | 写 |
| --- | --- | --- | --- |
| 1 | `Airflow` | `vel` | `vhat`、`q` |
| 2 | `AoA` | `a_dir`、`a_want`、`q`、参数表 | `cl`、`nose` |
| 3 | `Lift` | `a_dir`、`cl`、`q` | `acc` += |
| 4 | `Drag` | `vhat`、`cl`、`q` | `acc` −= |
| 5 | `Thrust` | `nose`、`proj_age`、`vel` | `acc` += |
| 6 | `Gravity` | — | `acc`.y −= `GRAVITY` |
| 7 | `Integrate` | `acc`、`pos`、`vel` | `vel`、`pos`、`proj_trav`，并公布这一腿 |

四个力 stage **只往 `acc` 里加**，改 `vel` 的只有 `Integrate`（子弹没有气动外形，
`Flights.Ballistic` 自己积它那一条抛物线）。前两个 stage 读的是同一份 tick 前状态，所以
一 tick 内的四个力是"同刻求和"而不是"分四步各改一次 `vel`"——顺序因此不是语义。
`Arm` 是本 tick 唯一的归零点，力和里不带上一 tick 的残余；`Integrate` 的末尾做一次
`maxvel` 归一化，重力与推力都不能把速度推过结构上限。

### 1.4 攻顶：一条参考弧，三段制导

发射架**固定在 42°**（`loft`，`bolted`，手臂怎么俯仰都不动它），20 m/s 软发射，0.15 s
后点火，110 m/s² 烧 3.4 s，燃尽时正好 306 m/s（0.9 M，硬上限：俯冲时重力也推不过它）。

爬升与俯冲是**同一条参考弧**的两半：一条以射程 `r0` 为底、顶点在射程中段的抛物线，
所以弹沿着弧上去、沿着弧下来，到末段**不需要急转弯**，落角自然收敛到 35–42°。
弧的顶点不是常量：`min(apex 950 m, 0.225·r0, r0² / (8·turn_r))`——近程被转弯半径压住
（1.26 km 以内是 `r0²/5600`），之后按 0.225 长高，950 m 的天花板要到 4.2 km 才碰得到。
一个 `loft` 同时定住爬升角与落角。

三段制导：

| 段 | 条件 | 律 |
| --- | --- | --- |
| BOOST | 发动机在工作 | 参考弧的斜率，且**不超过管子自己的 42°**（近目标时它把机头往下压） |
| GLIDE | 发动机已熄 | 同一条参考弧，无动力 |
| TERMINAL | 距目标 ≤ `pn_r` 且空速 ≥ `pn_v` | 真比例导引，N = 4，两个平面同时 |

**水平方向是比例导引，不是纯追逐**：巡航段与末段都让"到目标的连线的转动率"归零，只是
末段在三个平面里做、巡航段在地图平面上做（高度由参考弧的俯仰通道管）。纯追逐（对准目标
当前的方位再保持）会画一条本来不存在的曲线，代价是整段巡航的诱导阻力——对一辆横穿的车，
发动机有一大半花在自己的转弯上。这条律的输出是一个升力需求，
`Guidance.Top` 把它写成 `a_dir` / `a_want` 两列。所以打几百米外的车是这条弧最难
的场合：管子还在 42°，制导要的是**向下**的升力，弹被迫飞负攻角（钳在 −17.9°），机头压到
速度线下面，推力帮着往下按，阻力系数同时从 0.75 涨到 3.75（`cd0 + k_cl·cl_max²`）
——代价是真实的速度。

### 1.5 驾束：CLOS 定律与一条平飞的弹道

驾束弹没有弧。它被交给的是**一条线**（激光从发射机的光口指向 `Beams.intercept` 给出的
会遇点），每一 tick 它欠两样东西：

* **回到线上**：偏移量与偏移量的变化率一起归零，`a = K(d + ḋ·t_go) / t_go²`，
  `K = 16`（这条律的阻尼是 `sqrt(K)/2`，即 2），`t_go` 有 0.15 s 的下限。只追"点"的话
  （旧实现是追视线前方 90 m 的一个点）整段飞行都落后光束——实测 3 km 上差 18 m。
* **自己的重量**：`g` 在垂直于航迹的平面里的那一份是需求的一半，所以它靠一个**持续的
  攻角**托住自己（600 m/s 时 0.6°、400 时 1.3°、250 时 3.3°），并且一路付诱导阻力。

电机是**软发射 + 长推力**：40 m/s 出筒，0.4 s 滑行（16 m，离开车体）后点火，
100 m/s² 平推 7.3 s，正好在熄火时贴到 600 m/s 的上限。所以这条弹道是"越飞越快到最后"
——190 m/s @200 m、302 @500、420 @1 km、554 @2 km，熄火后开始掉速。每发弹还带一个
12 m/s² 的侧向推力偏心（`wob`，相位每发一个），制导每 tick 反着修，看得见的是尾迹上
一条几十分之一米的细纹。这条偏心不是升力，`Guidance.Saclos` 把它作为一条加速度直接加进
`acc`（该 pass 自己的 `_wobble_accel`），与其余四个力同刻求和。

**提前量是发射机的事，不是弹的事**：`Beams.intercept` 迭代三次，用的速度是这一发
**在途中平均**能达到的速度（发动机还亮着时取 `(当前 + maxvel)/2`）。拿 40 m/s 的出筒
速度去解提前量会算出一个 30 s 的飞行时间，把瞄点甩到目标航线一公里之外，随后随发动机
点火再一路扫回来。

### 1.6 游荡弹药：保高、盘旋、找到就扑

第三个制导律，也是唯一一条**自己找目标**的（找到之后归
[seekers.md](seekers.md) 管）。它没有电机窗口：推力 8.0 m/s² 的上限一直挂着，一台调速器
按速度误差开油门，平飞停在 0.66（5.3 m/s²，正好抵消阻力），速度因此是**巡航 41.7 m/s**；
爬升不需要额外指令——重力先让速度掉下来，调速器自己把油门推到满（+2.7 m/s² 的余量 =
最大 12 m/s 的爬升率）。`maxvel` 90 是结构上限，俯冲时重力把速度长到 50–60。

四个行为全部由状态导出，没有相位变量：

| 状态 | 律 |
| --- | --- |
| 没有锁，在盘旋点之外 | 直飞盘旋点（保高）：追一个不动的点，直线就是最短的 |
| 没有锁，已在半径内 | 沿盘旋圆飞（切线 + 半径偏差修正），同时扫描 |
| 有锁，距离 > `pn_r` | **平面比例导引**那个信念点（保高）——与攻顶弹的巡航段同一条律，N = 3 |
| 有锁，距离 ≤ `pn_r` | 真比例导引（三个平面），**不受保高管**：这一段就是俯冲 |

**保高**是"前方 300 m 的地面 + 200 m"的误差乘 `K_AGL` 0.15 s⁻²，再减去攀升率的阻尼
（`K_VY` 0.7 s⁻¹）：只有比例项的话，一个从地面起飞的弹会在高度上来回振荡，一路荡到电池
用尽。前方 300 m 的采样把 16 m 面片的地形噪声滤掉，也给爬升留出时间。倾斜转弯与爬升合成
一个升力矢量，被 `lift_max` 钳位；**钳位时先付高度、转弯用剩下的**，否则一个吃光升力的
坡度会把弹卷进地面。

**出筒那一程**是这条律唯一的硬约束：20 m/s、42° 出管，离地 2 m，而要爬 200 m。需求被
`CLIMB_MAX` 10 m/s² 截住（200 m 的误差乘 0.15 是 30 m/s²，远超 8.0 的推力上限），于是
10 s 进带、飞过 900 m 地面时到 206 m，此后阻尼把攀升率收回去，停在 205 m。有锁与无锁的
两发共用这一条曲线：高度通道只读前方 300 m 的地面，转弯的航向误差按地面航迹量。

**盘旋点**是开火那一刻瞄准点的水平位置：有锁时是那台车脚下的地面（打掉之后在原地等下一个
路过），无锁时是准星方向 3 km 处，AI 发射时是模式挑中的敌方城镇。半径 250 m（直径 500 m，
一圈约 36 s）。

搜索用的是一条固定 −30° 的光轴，所以在离地 200 m 上看到的是弹正前方 297–410 m 的一圈地面
（**环带**，114 m 深；斜距 358–456 m）。环带的近边比盘旋半径远，所以**压在盘旋点正下方
的一台车不在环带里**，要开出去才会被看见；一趟侧扫 2 s（±40°、40 °/s），同一个方位 4 s
才回一次，一辆 27.8 m/s 横穿环带的车可能整圈没被扫到。两者都由几何给出，是这条律的边界
而不是缺陷；**锁着发射不受影响**——目标位置与速度已知时，350–800 m、0–50 m/s 的目标全部
命中。

### 1.7 电池与导线是两种寿命

一颗弹的寿命写在 `life` 里，`maxdist` 是导线/指令链的长度。`Expire` 在**任何飞行之前**
把它们数完：

* 到 `life`：`expire_burst` 为真（攻顶弹与游荡弹药的电池）就**原地起爆**，为假
  （子弹、无制导火箭、驾束弹）就安静消失；
* 到 `maxdist`：**一律起爆**——导线尽头那 6 m 内照样吃爆炸；
* 两种都在 `first_hit_record` 里写成 t = 0 的一次接触，所以 `Impact` 不必为"超时"单开
  一条分支。

攻顶弹的射程上限因此是**电池**而不是发动机：30 s 到期，静止车约 4.3 km、在跑的机甲
3.5–4 km；驾束弹的导线是 4 km，也是它的射程。游荡弹药没有导线，电池 300 s 就是它的
全部寿命：爬升 10 s、飞 4 km 用 96 s，剩下 194 s 在盘旋点转五圈，到期原地自爆。

游荡弹药巡航速度上 20.9 m/s²（2.1 g），盘旋（250 m 半径）用掉 58 %，俯冲时随
`q` 长到 30 以上。

**巡航段为什么是比例导引**：`--check drone` 的"横穿"行摆了一辆以 27.8 m/s 横穿飞行线的
装甲车，同一发弹从 1442 m 斜距起飞。比例导引把连线转动率归零，它沿一条近似直线的斜交航路
切入；纯追逐会先拐向那辆车**当时**的方位、再一路修正。这条几何里两者的差是 1752 m / 41.0 s
对 1788 m / 42.1 s（2 %）；车越快、越远，纯追逐的那条曲线越长，而巡航速度由调速器钉住，
所以这份代价全部落在"到达时间"和"进入末段时的能量"上。

## 3. 判定与边界

* **一步 1/30 s**。速度先积分、位置再走（半步欧拉），与 `Ballistics.flight_at` 和客户端
  `core/fcs.js` 的 `flightTo` 完全一致——三者不一致，准星上的距离就不再是弹着的距离。
* **靠近目标就一定会掉出弧**。弧是按"还有多少路"算的，射程越短顶点越低；把管子恒定在
  42° 就是为了让近距那一发靠负攻角硬压下来。
* **初速上限是结构上限**，不是发动机上限：推力只在 `age ∈ (ignite, ignite+burn]` 且
  `speed < maxvel` 时给，所以熄火之后速度只会掉。
* **没有制导就没有升力需求**：驾束弹失去激光（发射机死了、山脊切断了光束）或攻顶弹
  从来没锁上时，制导停、发动机与阻力照旧，于是它像一块石头一样掉下去。无制导火箭是这条
  规则的极端情形：升力需求从第一 tick 起就是零，付的只有剖面阻力与跨音速项。
* **`maxvel` 与速度上限是同一件事**：`Integrate` 每 tick 归一化一次，重力与推力都不能
  把它推过 `maxvel`（这就是"0.9 M 是硬上限"）。
* **投射偏心的相位每发不同**（种子在出膛时定），弹体不滚转。

## 4. 设计与取舍

* **飞行体取代了折线**：旧实现是"沿手画路径以固定转弯率前进的点"——没有质量、没有
  攻角、没有能量，于是"拉一次要不要付速度"这个问题根本问不出来。改成这副气动外形之后，
  射程、落角、末段能不能修正，全从一个 `cl_max` 与一个 `q` 里长出来。
* **气动外形是数据，不是开关**：两种弹只差一张参数表，同一个 stage 同时飞它们；换弹种
  是填表。每一项力的算式就住在施加它的那个 stage 里（`Systems/Flights/Airframe.cs`），
  两条制导律住在各自的制导 pass 里（`Systems/Flights/Top.cs` 的参考弧与 PN，
  `Systems/Flights/Saclos.cs` 的 CLOS）——只有一个使用者的算式不另存一份。
* **中间量在组件里，算式在 stage 里**：stage 之间只通过组件传值（`vhat` / `q` / `cl` /
  `nose` / `acc`），所以一条力的链条一步就能读完。唯一需要"不搭世界就能飞一发"的调用方
  是火控（`Ballistics.flight_at` 解仰角时要飞一遍即将打出的无制导火箭），它要的那一发
  没有升力需求，所以 `Core/Flight.cs` 只保留 `Flight.slide`（无制导那一发）与几个共用常量
  和 `area`；`--check airframe` 量的是它与七个 stage 还是不是同一条定律。
* **组件集合就是身份**：一颗弹的七列气动状态在出膛时一次给齐（`Components.AIRFRAME_EXTRA`，
  15 个 float），之后任何 stage 都不增删组件，所以一 tick 内的行号在十一个 pass 之间不变；
  子弹不带这些列，七个 stage 对它按构造就不存在，不需要任何 `kind` 分支。同时在飞的有翼
  弹是个位数。
* **一条参考弧顶替一次末段急转**：抛物线的前半段是爬升、后半段就是俯冲，落角于是是
  设计出来的，不是被逼出来的。
* **驾束把"打中"放在机器上**：弹只有一台发动机、四片舵和一只收激光的屁股；找到、
  提前、指住都是发射机的活。见 [seekers.md](seekers.md) 与 [firecontrol.md](firecontrol.md)。
* **提前量用平均速度，不用当前速度**：这是唯一一处"飞行系统必须知道自己的发动机"的
  地方，而它换来的是瞄点不随点火扫过整条航线。
