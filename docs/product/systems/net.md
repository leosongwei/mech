# 线路：帧格式、分层快照、时钟、拥塞与小地图

> **读者**：机制维护者 / 外部集成
> **一句话**：服务端每 tick 发什么、一位飞行员到底收到多少字节、链子堵了的时候怎么判断"堵"而不是"远"，以及小地图为什么不走快照。
> **数值出处**：`Net/Netcode.cs`（`ROWS` / `ROW_*` / `TIER_*` / `CONTACT_*` / `FX_STRIDE` / `CLOCK` / `HEADER` / `snapshot_bytes` / `contacts_bytes` / `meta_payload` / `hearable`）、`Net/Server.cs`（`SNAP_EVERY` / `META_EVERY` / `IDLE_SLEEP_MS` / `Client.observe` / `game_loop`）、`Systems/Datalink.cs`、客户端 `frontend/src/net/*.js` 与 `core/config.js`（`TICK_HZ` / `SNAP_HZ`）
> **核对**：1.45.0 / 2026-11-25

## 1. 规则

### 1.1 一 tick 一帧，而一帧的第一件事是时钟

每个 tick，每位飞行员都会收到**一个二进制帧**：每两个 tick 里有一个是快照，其余每 tick
是**只带时钟块的那一帧**。所以健康连接拿到的是 **30 帧/s**，而不是 15 帧/s 加上一段猜测
（fx 事件另走自己的帧，见 §2.2）。

时钟与画面彻底分开，是这一条的整个目的：客户端读到的 tick 号、往返时间、服务端的实际
帧率、自己丢了多少，都来自同一个 16 B 的块，与"这一帧有没有画面"无关。

其余三块按各自的节奏搭车：**小地图**（每 8 tick，半径块搭在快照里，行数写在帧头，0 表示
这一帧没有新图）、**fx 事件**（每 tick，有事件才发一个自己的二进制帧）、**meta**（每 3
tick，一条独立的 JSON 消息）。

### 1.2 快照是一个以眼睛为心的球

一帧快照不是整张地图：它是**以这位飞行员的眼为心**的一串球，每个类一个半径。球外的行
根本不构建，所以省的是"构建 + 字节"两笔账。半径是客户端自己的常数反过来定的，不是口味：

| 半径 | 载什么 | 背后那条客户端常数 |
| --- | --- | --- |
| 6 km | 机甲、装甲车、靶场碉堡、烟 | 调零的 4 km 与激光的 4 km：HUD 就按这些行解算 |
| 4.5 km | 制导弹（火箭、SACLOS、攻顶） | 制导臂的锁距 4 km：弹一离管就得在画面里 |
| 4 km | 残骸、子弹 | 一辆车在 4 km 上还算"在画面里" |
| 3 km | 步兵、平民 | 他们是场上的绝大多数，几百米外就看不见 |
| 2 km | 其他一切 | |
| 无限 | 飞行员自己的车体、两座指挥部 | 见 §3 |

分层之前先按接收方阵营过滤未知敌方装甲：当前没有同阵营数据链接触的敌方 MECH / APC
不进入快照。友军位置始终共享；自身与两座指挥部保留豁免。数据链不扩大任何 tier，也不把
未知目标放进死区保留集合。

### 1.3 行是分行宽的

一条单位行有多宽，取决于**读它的那一层需要什么**：一台机甲行 76 B（视线头、双臂、弹药、
模块血、观瞄孔径），一辆装甲车 48 B（炮塔、提前量环、观瞄孔径），一座指挥部 30 B（炮与
完整度），残骸与碉堡 25 B（一个姿态加残骸标志），一个步兵 20 B（一个点和朝向）。曾经人人
80 B，一个步枪兵为机甲的弹匣与观瞄塔付 56 B，其中 `pad3` 与 `hp[1]` 从来没被写过——那是把
堆里的字节发了出去。

机甲与装甲车行尾那 2 B 是 `gaze`：机组的**观瞄孔径**朝哪（u16 覆盖一整圈，0.0055 度）。
它与 `syaw` 是两个不同的方位——炮口与眼睛各有各的主（[ai.md](ai.md) §1.4）——而它是玩家
判断"对面看没看见我"的唯一读法。零头是这么算的：两字节买 0.0055 度，同理 `hp` 只要
整数。步兵行不带它：人体模型上没有可转的部件，而步兵是场上最多的一行，2 B × 几百行买不到
可读性。没有机组的壳子（玩家的机器）写自己的炮口方位顶替，所以客户端不需要问"这台车是
不是 AI"。

### 1.3.1 数据链能力位与按接收者过滤

* init JSON 固定带 `"datalink": 1`。MECH / APC 的 `flags` **bit6** 是 `TARGET_LINK`，按
  接收者写入：友军车辆与已通过当前数据链过滤的敌方接触置位，bit7 保留。
* 弹丸行 **`+5` bit0** 是 `TARGET_LINK`。友军 SACLOS / 攻顶弹始终置位；敌方制导弹只在本
  tick 有车辆观察到时置位，`+6..+7` 保持零。无制导火箭不使用这一位。
* 弹丸行本身不按数据链删除，tier 与死区仍按原规则执行；`TARGET_LINK` 只告诉客户端这行
  是否也可作为共享观察来源。车辆行则在 tier 判断之前过滤，未知敌方装甲不会进入 `keep`。
* 普通世界快照中的步兵仍按原 tier 发送。小地图 `contacts` 不发送步兵、平民或尸体；其中
  敌方 MECH / APC 同样要先通过当前数据链过滤，其他非人员实体沿用原规则。
* 每个 contacts tick 最多构建红、蓝两份字节，同阵营玩家共用对应一份；`contacts` 不分 tier。
  观察资格、当前有效性与失效时刻归 [sight.md](sight.md) §1.7。

行宽不因这些字段改变：`ROW_MECH=76`、`ROW_VEHICLE=48`、`PROJ_STRIDE=32`，帧长仍由实际
行数计算。

### 1.4 拥塞是排队，不是距离

判断一条链子堵没堵，看的是"这位飞行员看到的最新一帧有多旧"与**他自己这条路上最好的
那个读数**之差。一个 200 ms 外、线路干净的玩家不堵；同一个玩家前面压着 400 ms 的队列
就是堵。所以：

```
behind_ms = (tick - ack) × 1000/30
floor_ms  ← 立刻取更小的样本，每秒只涨 2 ms（被 held 超过 10 s 后涨 20 ms/s），上限 2 s
slack     = max(200 ms, floor_ms × 0.75)
held      = 沉默 > 0.4 s  或  behind_ms - floor_ms >= slack
resumed   = behind_ms - floor_ms <= slack/2  且  发送队列已空
```

被 held 的飞行员**只收到时钟块**，快照、fx、meta 一概不构建。降低帧率救不了一条堵住的
管子：排队里的每一帧都要先爬过去，画面才动。

### 1.5 空服暂停

没有连接时，主循环**什么都不算、什么都不发**，只是睡觉（0.1 s 一次），并把下一个 tick
的时刻重置到当下——世界从最后一帧的地方干净地接着跑，而不是补上它站住的那段时间。所以
一位飞行员过一小时回来，看到的是他离开时的战场，而不是一场已经打完的战争。

`MECH_DEBUG=1` 关掉暂停（那是脚本与外部观察用的运行）。`GET /events/kills` 的读者是
听众、不是飞行员：它拿到自己的心跳，世界仍然暂停，细节见
[../interfaces/kills_sse.md](../interfaces/kills_sse.md)。

## 2. 数值表

### 2.1 节拍

| 项 | 值 |
| --- | --- |
| tick | 30 Hz（`TICK_DT` = 1/30 s）|
| 快照 | 每 2 tick = **15 Hz** |
| 时钟块帧 | 其余每 tick，即健康连接下 30 帧/s |
| `meta` | 每 3 tick = 10 Hz（JSON）|
| 小地图块 | 每 8 tick = **3.75 Hz**，与快照同一帧 |
| fx 行 | 每 tick，有事件才发（独立二进制帧）|
| 空服睡眠 | 0.1 s |

### 2.2 帧

```
二进制帧开头 16 B 的时钟块（三种 magic）：
  MECH  快照（= 时钟块 + 八项 u16 计数 = HEADER 32 B + 行）
  MECP  只有时钟块（hold 帧，也是非快照 tick 的那一帧）
  MECF  fx 行（6 B 头 + 24 B × 事件数）
HEADER 里的八项计数：5 个单位类 + 弹丸 + 烟 + 小地图行数
```

| 项 | 字节 |
| --- | --- |
| 时钟块 `CLOCK` | 16 |
| 帧头 `HEADER` | 32（时钟块 + 八项 u16）|
| 机甲 / 装甲车 / 指挥部 / 残骸·碉堡 / 步兵·平民·尸体 | 76 / 48 / 30 / 25 / 20 |
| 弹丸、烟 | 32 / 32 |
| fx 行 | 24 |
| 小地图行 | 6 |
| meta | 约 1.9 kB（JSON，10 Hz）|

### 2.3 时钟块的五个字段

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `magic` | u32 | 帧的种类（`MECH` / `MECP` / `MECF`）|
| `tick` | u32 | 世界时钟 |
| `echo` | u32 | 这位飞行员**自己的 ack** 被原样送回，RTT 就测在它上面 |
| `tps` | u16 ×100 | 服务端上一秒真实跑出来的 tick 率（追不上就报小于 30）|
| `loss` | u16 ×10000 | 这位飞行员上一秒没发出的快照比例（被 held 时读 100 %）|

### 2.4 小地图块

| 项 | 值 |
| --- | --- |
| 一行 | 6 B：x、z（u16）、faction、etype |
| 量化 `CONTACT_QUANT` | **8 m**（16 km → 2000，u16 上限 524 km）|
| 内容 | 非人员实体按原规则发送；敌方 MECH / APC 须有当前数据链接触，不分层 |
| 帧 | 每 8 tick 搭在快照上；行数在帧头里，0 表示"这一帧没有新图" |
| 缓存 | 红、蓝各一份；同阵营玩家共用对应字节 |
| 分辨率对照 | 210 px 的地图上一个像素约 76 m，所以 3.75 Hz 看不出步进 |

### 2.5 初始载荷

地图与全部定义只发一次：高度用 u16（**5 cm** 一步，`H_UNIT`），三张位图，城镇、据点、
车道、颜色、名称、单位表、管阵参数，以及能力声明 `"datalink": 1`。整包
`base64(zlib(bytes))`，因为客户端的 JS 解压需要一个 zlib 头。它在启动时构建一次，所以
16 km 地图的生成（约 0.7 s）只在开服时付。

## 3. 判定与边界

* **自身与指挥部豁免是承重的**：飞行员**自己的车体**与两座**指挥部**总在快照里；前者
  保证客户端有本地机体，后者保证顶栏完整度条不闪烁。友军位置另由同阵营共享规则直接发送。
* **进 R、出 1.15 R**：上一帧载过的行，这一帧可以撑到 1.15 倍半径才消失。客户端会删掉
  新帧里没有的实体，没有这条滞回带，停在一个圆上的车体每过一次圈就被重建（位置跳、
  平滑被打断）。数据链过滤先于死区：当前未知的敌方装甲不进入 `keep`，不会多留一帧。
* **慢连接靠丢弃保住 tick**：发送队列 24 帧，`TryWrite` 失败就记 `dropped`，于是 30 Hz 的
  tick 一直往前跑。**已构建的帧一帧都不丢**，所谓"丢掉的快照"是从没被构建的那一帧。
* **RTT 要减半个 tick**：服务端在 socket 线程读 ack，但只能在自己的**下一帧**把它 echo
  回来，即等待时间在一个 tick 上均匀分布、平均半个。样本是
  `现在 - ack 首次发出时刻 - 500/30 ms`（我们这一侧不再减，打戳就是发出的那一刻），
  EMA 0.15 平滑。比这更快的链路上样本会略微为负，HUD 在负值（以及还没有第一个样本时）
  画一个固定宽度的 `-`，后面的数字就不会抖。
* **ack 早于连接不算距离**：一条 `st` 报得比 `born_tick` 还早的读数被丢弃——新客户端在
  tick 4000 时报 `st: 0` 会凭空塞进 133 s 的"队列"。没报过 ack 的客户端同样不判距离，
  只有沉默能 hold 它。
* **`loss` 的窗口是一秒**：`WINDOW` = 30 tick 闭合一次，`skipped/due`；被 held 的一秒
  因此读 100 %。
* **HUD 的橙字判据是"没有快照"**：`net.held` 是"超过 4 tick 没有快照"（快照本来每 2
  tick 一次），所以一半帧是时钟块这件事不会被当成 hold。`PING` 是**往返**、不减半，
  与 `TPS`、`LOSS` 印在右下角同一行，见 [../hud/hud.md](../hud/hud.md)。
* **声音按耳朵过滤**：`hearable` 用与客户端同一个衰减律把听不见的事件从这位飞行员的 fx
  里剔掉，消息类事件照发；细节见 [audio.md](audio.md)。

## 4. 设计与取舍

* **时钟不该跟着画面变**：帧数一少，客户端的时钟就一步一步跳。加一帧 16 B 的时钟块，
  代价是 0.2 kB/s（占 68 kB/s 的 0.3 %），换来一个与画面无关的时钟。
* **分层是"以眼为心"，不是"全图发一遍"**：一整张 16 km 图、300–400 行、90 % 是步兵，
  不分层时 468 kB/s，其中 94 % 是快照。按球裁开、按类分行宽、fx 改行之后是 67.8 kB/s。
* **为什么行宽要按类分**：一位飞行员的带宽里最贵的东西是"他没有读的字段"。分行宽是这条
  原则唯一能落到字节上的做法，代价是客户端每一类开头先把自己不带的那几列清零（实体 id
  会被回收，一个步枪兵不能继承一台机甲的弹匣）。
* **小地图只能自成一块**：16 km 的战略图给不了"某一双眼睛周围的球"，而它的信息量又只需
  要每秒四次。它仍不分层，但按阵营过滤；服务端每个 contacts tick 最多构建红、蓝两份，
  同阵营玩家共用对应一份。
* **拥塞判据必须相对自己的路**：拿绝对延迟当拥塞，会把远在千里之外的玩家永远按住——实测
  233 ms 与 666 ms 单向延迟都读到"堵"，画面无故掉成时钟块。
* **floor 会退让**：一直涨的上限会把真正的路径变慢当成一次坏样本；被 hold 超过 10 s 之后
  涨幅从 2 ms/s 提到 20 ms/s，一条真的变慢的路会自己走出来。

## 5. 实测

```bash
./dotnet.sh run -- --check net --minutes 30 --from 8   # 一位飞行员的下载，按分钟
./dotnet.sh run -- --check tiers --minutes 8           # 在同一场战斗上给另一张分层表定价
./dotnet.sh run -- --check datalink                    # 阵营过滤、contacts 与两个能力位
```

| 读数（`--check net`，分钟 8–15 的平均） | 值 |
| --- | --- |
| 总收入 | **67.8 kB/s** |
| 快照 | 45.5（其中小地图块 6.7），53 条单位行、平均 36 B |
| meta | 18.4 |
| fx | 3.7 |
| 时钟块 | 0.2 |
| 不分层 | 468 kB/s 平均 / 523 kB/s 峰值，94 % 是快照 |
| 分行宽之前 | 112 kB/s |
| 整场不分层会是多少 | 168 kB/s |

拥塞与 RTT 的手工验证（Node 探针注在不同延迟上）：233 ms（7 tick）与 666 ms（20 tick）
都是 15 快照/s、零 hold；ack 冻结 → 一个 tick 后 `held: 267 ms behind (floor 34, slack
200)`，随后 30 帧/s 的时钟块与 `loss 100.00 %`；3 s 的队列 → `held: 533 ms behind`，
队列排空后 `resumed after 45 clock blocks`。回环上的 RTT 样本 21.6 ms 平均，减半 tick
之后与 16.7 ms 的真实等待对齐（减一整 tick 的旧版在快链路上永远读 0）。
