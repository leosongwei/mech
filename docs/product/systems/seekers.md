# 锁定、导引头与激光通道

> **读者**：机制维护者 / 调参
> **一句话**：一台机器怎么"选中"另一台车、锁住之后视线被切断还剩下什么、弹在空中的
> 导引头在追哪个点、以及它为什么会换一台车。
> **数值出处**：`Core/Defs.cs` 的 `LOCK_FRAC` / `BASE_FOV` / `SEEKER_CONE` /
> `AIM_ROOF` / `BEAM_CHANNELS` / `BEAM_CONE` / `BEAM_MEMORY` / `BEAM_ACCEL_TAU`；
> 服务端 `Systems/Locking.cs`、`Systems/Beams.cs`、`Core/Seeker.cs`
> **核对**：1.39.0 / 2026-11-20

## 1. 规则

### 1.1 一次锁定：圈压上去就是锁上了

两种制导弹（红外攻顶与激光驾束）问飞行员的是**同一件事**：把准星圆圈压在敌车上。
条件四个，缺一不可：

* 目标是**可锁定的**单位：机甲与 APC（`lockable`）。步兵、平民、残骸、飞来的弹都不行。
* 距离在 **4 km 以内**（`lock_range`，两种弹一样）且**大于 20 m**；
* 视线**通得过**（地形、建筑、树冠、烟幕，同一条视线，见 [sight.md](sight.md)）；
* 目标落在这个圆圈里。圆圈的角半径是"视口宽度 5 %"折算出来的：
  `atan(tan(fov/2) · LOCK_FRAC · aspect)`，而 `fov = 1.05 / 倍率`。

**没有保持时间**：进圈那一帧就锁上，同一帧就能扣扳机；也**没有滞回带**——红外导引头
的候选一离开圆圈就脱锁。客户端如何画这个圈（粗细、颜色、圈心菱形）在
[../hud/aim.md](../hud/aim.md)，圈随倍率变窄的后果在这里：1x 时约 0.051 rad，
10x 时约 0.0047 rad，所以高倍镜里挑目标更准。

**锁属于机器，不属于人**：通道是机甲（或 APC）身上的一个组件，机器死了锁跟着死，而线上
的 `lock_target` / `locks` 只是给 HUD 的镜像。

### 1.2 候选会黏住

准星压在敌车上只是**候选**（`Player.lock_target`，HUD 上的粗菱形）：它不占任何资源。
它**一旦被点名就留在那台车上**，即使准星移开——直到准星压上另一台车，或者它死了、跑出
`lock_range`。

这是为**带提前量的武器**设计的：这一发要瞄的是目标未来的位置，准星必须能离开车身。
如果候选跟着准星走，飞行员就在"瞄准"和"有个目标"之间二选一。

### 1.3 导引头记忆：一个点，一个速度

红外弹的锁定不是存一个 id，是存**两个数**（组件 `tgt_mem` / `tgt_vel`）：

* `tgt_mem`：凝视点——车顶甲板，`pos.y + AIM_ROOF × 车高`。
* `tgt_vel`：那台车**最后一次被看见时真实在跑的速度**（`vel`，不是指令速度
  `vel_cmd`，否则驾驶员一推杆弹就被一个 50 m/s 的幽灵带走）。

视线通得过时，两者每 tick 刷新成真身；视线一断（烟、山脊、树冠、房子、目标死了），
凝视点**按那个速度继续走**，而制导根本看不出来——它拿到的一直是"一个点 + 一个速度"。
**没有加速度项**：被切断之后的记忆是一条直线。这一步和驾束通道的 `_walk` 是同一个形状。

### 1.4 重捕：锥里最近的那台

被切断的弹每一 tick 问一个问题：**凝视线上 3° 以内，有没有一台我能看见的敌车？**

* 判据是候选的**甲板**（它会被俯冲的那个点）离凝视线多远；1 km 上 3° 只有几十米宽；
* **排序看的是到凝视点的距离，不是离视线的角度**。齐射就是齐射：四发弹各盯着自己那个
  推定点，按角度排序会把它们全引到最靠近那条线的同一台车上——一台车吃满四发，另外三台
  开走。按推定点距离排序，每发回到自己那台车身上。
* 只分敌我，**不管是不是原来那台、也不管是机甲还是 APC**：一辆车开进射击线，它就是目标。
* 每个候选都要过 `Sight.clear`——弹抓到的权限是它看得见的东西。躲在烟里、楼后的车不会
  被重捕，但"看不见"不等于"打不中"：弹继续朝推定点俯冲，落点就是它算错了的地方。

所以想真的打空，得**在烟里变向**，或者钻进建筑/山体后面让推定点落在遮挡物上。目标被打死
也一样：那一发炸在"它本该在的地方"，除非锥里出现了别的敌车。

### 1.5 那一发是从什么开始飞的

`Weapons.fire` 在出膛那一刻把记忆写进弹里，写的是**射手的信念**，不是真身：

* **飞行员**：客户端每帧把 HUD 画的那个点随输入发上来（`in.lb` =
  `[id, x, y, z, vx, vy, vz]`）。它只在这台车的候选上生效、只在 **0.5 s 内**（15 tick）
  生效、只在 `lock_range × 1.5` 以内生效——超出任何一条就退回真身播种。
* **机组**：交出去的是自己瞭望维护的那一份（`ai_tgt`，位置 + 速度 + 多久之前真的看见
  的），抬到甲板高度。所以"照着知道的打"对人对机组是同一条规矩。
* **脚本射手**（靶场的固定靶、检查程序）没有信念列，从车身本身开始——它的视线就在那儿。

**视线断了照样可以扣扳机**：候选还在，弹就带着这个推定点起飞。

### 1.6 驾束：四条通道、40° 锥、8 s 记忆

激光驾束弹自己不会找目标。**机器**是最多 `BEAM_CHANNELS` = 4 条**通道**，一条通道 =
一台被正式照着的车；激光在它们之间高速切换，束里编码了弹的编号，所以四发弹各骑各的线。

一条通道每 tick 维护一个**轨迹**：瞄准点、目标的速度、测到的横向加速度（0.25 s 时间常数
平滑，一次超过 25 m/s² 的跳变判为传送），以及**视线被切断多久**。

| 状态 | 行为 |
| --- | --- |
| 看得见 | 每 tick 用真身刷新轨迹 |
| 看不见，≤ 8 s | 按最后速度 + 测到的加速度**走**（加速度只信 1 s，与全场的提前量同一个秒数） |
| 看不见，> 8 s | **停在那里不再外推，激光熄灯**（`beam_ok` 归 0）——这么旧的猜测不值得照 |

熄灯不等于脱锁：那台车仍然是这台机器的，重新露出来、还在锥里，**当帧重新点亮**，还在
空中的弹又能修正。

**40° 锥是硬限制**：激光是"指"过去的，所以这条通道能被指在以视线为轴、半角 40° 的圆锥
里的任意方向，**与倍率无关**（1x 和 20x 都是这个锥）。目标（或它的推定点）走出这个锥、
或者超出 `lock_range`、或者死了，通道才撤销。飞行员还得把准星压在车上才能**取得**候选，
但已经拿住的车是机器在跟，所以缩放不会把锁收窄。

**第五个目标顶掉最老的那条**（掰一个丢一个），被顶掉的那一发立刻失去修正、顺着当时的
航向掉下去。一条通道是**扣扳机的那一发**占下的：准星扫过四台车只是换了四次候选，不会
占通道、也不会挤掉已经在照的正式目标。

`Weapons.fire` 为它要打的这台车 `Beams.lay` 一条线：已经有线就用那条，没有就新开一条
（新开的当帧立刻采样一次，所以"同一 tick 锁上并开火"也有线可骑）。

### 1.7 候选、正式目标，以及画在哪

* **粗菱形**（`lock_target`）：准星命名的那台车，扣扳机打的就是它。
* **细菱形**（`locks`）：激光正式照着的车，一条通道一个，最多四个；候选本身已经被一发
  弹占过通道时画成细的（"已经在照"）。
* 两种武器共用同一个"标记画在哪"的规矩：**画在信念点上**，看得见就是车身、看不见就按
  测到的速度走、变淡。具体像素与变淡比例在 [../hud/aim.md](../hud/aim.md)。

## 3. 判定与边界

* **锁定判车体中心，弹判甲板**。获取（`Locking`）看的是车高 50 % 的几何中心；弹的导引头
  （`Seeker.acquire`）与命中判据看的是 78 % 的甲板。1 km 上这两点差三分之一度，是锥宽的
  五分之一——两处都各有理由，别把其中一个改成另一个。
* **凝结点必须落在命中球内**。旧值 92 % 的机甲是 5.98 m，而躯干球顶在 5.45 m：每一发
  导得完美的弹都从车顶半米上掠过、炸在车后的土里（靶场实测 5 次俯冲有 2 次如此）。
  0.78 把瞄点放进躯干球里 0.38 m——还是甲板，但照着它飞就是命中。
* **锁定需要视线，保持不需要**（驾束）／**保持需要视线，切断就脱锁**（红外）。两个武器
  同一个获取交互，保持规则不同，这是设计而不是遗漏。
* **烟幕是掩体，不是打空**：断锁只是"看不见"，弹照飞它的剖面。
* **步兵与平民锁不上**；`lockable` 是组件，所以残骸、飞弹、烟球也锁不上。
* **没有候选就扣不动扳机**，HUD 读 `NO LOCK - IR SEEKER HAS NO TARGET` /
  `NO LOCK - LASER HAS NO TARGET`，并放一声拒绝音。
* **脱锁与重捕都不提示玩家**：服务器在 DEBUG 级别记两行（`... lost the lock ...:
  smoke|terrain on the line of sight` 与 `... re-locked on hull N ...`），客户端只让
  标记变淡或跳回车身。弹不再压向自己时，告警盘上的红指针和告警音会自己停。

## 4. 设计与取舍

* **锁是一个点 + 一个速度，不是一个实体**。制导于是看不见"目标没了"这件事：一条过期的
  凝视点与一条刚测到的走同一条代码路径，所以丢失期间弹道剖面与保持期间一模一样。
* **重捕按距离排序**：齐射时按角度排序会把一整轮火力堆到同一台车上，这是实测过的行为，
  不是理论担忧。
* **锁定没有保持时间**：加一段"稳定一下"只会在最紧张的那一帧里拿走扳机。
* **候选黏住准星**：带提前量的武器必须允许准星离开车身。
* **通道由弹占、不由准星占**：否则准星在找目标途中扫过四台车就填满通道并顶掉自己真正
  在打的那一台。
* **8 s 之后熄灯但保留锁**：一条太旧的猜测不值得照着飞，但目标是这台机器的——所以它回来
  的时候不需要重新"取得"。

## 5. 实测

`--check beam`（1.39.0，`./dotnet.sh run -- --check beam`）：

| 行 | 读数 |
| --- | --- |
| `belief` | 无信念时从记忆起飞（离车 2 m、离走出来的推定点 134 m）；视线断 1.5 s、车掉头后凝视点只走了 34 m，锁开着但离车 178 m；屏幕升起当帧回到甲板 0 m 并重捕。 |
| `ghost` | 30 m/s 横穿、1 s 断视线：1 s 差 3 m、3 s 23 m、5 s 71 m、7 s 95 m；8 s 之后观众重新点亮、位置又回到 3 m。 |
| `held` | 跟随时亮、被屏幕挡住仍亮且差 3 m、猜测过期变暗（仍差 3 m）、屏幕升起重新点亮。 |
| `lock` | 没有候选的 14 次扣扳机只出了 1 发（门是有效的）。 |
| `channels` | 打四台不同目标：四条通道全部拿住；第五台顶掉最老的（FIFO）。 |
| `paint` | 视线在车上：1 个照射标记；视线偏 22 m：没有；锁住但准星偏 25°：仍有标记；被烟挡住：没有（激光不在车上、锁还在）；烟散去：有；中间隔着一台车：没有；看别处：通道让出。 |
